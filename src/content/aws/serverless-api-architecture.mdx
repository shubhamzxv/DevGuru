<Analogy>

A **cloud kitchen** with no restaurant of its own. Orders arrive through a delivery app (API Gateway, which checks the customer is real), cooks are called in only when there is an order (Lambda), and the pantry is a self-restocking store (DynamoDB). When nobody orders, nobody is paid; on festival nights a hundred cooks appear automatically.

</Analogy>

## Simple explanation

```text
Client ── HTTPS ──▶ API Gateway (HTTP API, JWT authorizer: Cognito)
                        │  POST /orders, GET /orders
                        ▼
                    Lambda (Python) ── IAM role (least privilege) ──▶ DynamoDB table "orders"
                        │
                        ├─▶ EventBridge "OrderPlaced" ─▶ SQS ─▶ Lambda: email / invoice
                        └─▶ CloudWatch Logs + X-Ray
```

| Layer | Service | Notes |
| --- | --- | --- |
| Front door | API Gateway HTTP API | routes, CORS, throttling, custom domain |
| Auth | Cognito user pool + JWT authorizer | user id from `claims.sub` |
| Compute | Lambda | one function per route or one per service (a "lambdalith" with a router) |
| Data | DynamoDB on-demand | single-table design: `USER#id` / `ORDER#id` |
| Async | EventBridge / SQS | slow work outside the request |
| Files | S3 presigned URLs | uploads go directly to S3 |
| IaC | SAM or CDK | whole stack in one template |
| Observability | CloudWatch Logs, metrics, X-Ray, Powertools for AWS Lambda | structured logs, tracing, idempotency utilities |

**Strengths**: no servers to patch, automatic scaling, pay per request (near zero at low traffic), fast to build.

**Watch out for**: cold starts (keep packages small, init outside the handler), 29 s API timeout and 15 min Lambda limit, DynamoDB access-pattern design, high steady traffic can cost more than containers, local testing (SAM local, moto, unit tests on handlers), limits on concurrency (reserved concurrency to protect downstreams).

## Code example

The function (`src/app.py`):

```python
import json, os, uuid, boto3
from decimal import Decimal

table = boto3.resource("dynamodb").Table(os.environ["TABLE"])      # created once per environment

def num(d):
    return int(d) if d == d.to_integral_value() else float(d)      # DynamoDB returns Decimal

def resp(code, body):
    return {"statusCode": code, "headers": {"Content-Type": "application/json"}, "body": json.dumps(body, default=num)}

def handler(event, context):
    route = event["routeKey"]
    user = event["requestContext"]["authorizer"]["jwt"]["claims"]["sub"]
    if route == "POST /orders":
        body = json.loads(event.get("body") or "{}")
        if not body.get("items"):
            return resp(400, {"error": "items required"})
        total = sum(Decimal(str(i["price"])) * i["qty"] for i in body["items"])
        oid = str(uuid.uuid4())[:8]
        table.put_item(Item={"pk": f"USER#{user}", "sk": f"ORDER#{oid}", "total": total, "status": "placed"})
        return resp(201, {"id": oid, "total": total})
    if route == "GET /orders":
        items = table.query(KeyConditionExpression="pk = :p AND begins_with(sk, :o)",
                            ExpressionAttributeValues={":p": f"USER#{user}", ":o": "ORDER#"})["Items"]
        return resp(200, [{"id": i["sk"][6:], "total": i["total"], "status": i["status"]} for i in items])
    return resp(404, {"error": "not found"})
```

The SAM template (`template.yaml`, passes `cfn-lint`):

```yaml
Transform: AWS::Serverless-2016-10-31
Globals:
  Function: { Runtime: python3.13, MemorySize: 256, Timeout: 10, Architectures: [arm64] }
Resources:
  OrdersTable:
    Type: AWS::DynamoDB::Table
    Properties:
      BillingMode: PAY_PER_REQUEST
      AttributeDefinitions: [{ AttributeName: pk, AttributeType: S }, { AttributeName: sk, AttributeType: S }]
      KeySchema: [{ AttributeName: pk, KeyType: HASH }, { AttributeName: sk, KeyType: RANGE }]
  HttpApi:
    Type: AWS::Serverless::HttpApi
    Properties:
      Auth:
        DefaultAuthorizer: Cognito
        Authorizers:
          Cognito:
            IdentitySource: $request.header.Authorization
            JwtConfiguration:
              issuer: https://cognito-idp.ap-south-1.amazonaws.com/ap-south-1_AbCdEf123
              audience: [3n4b5c6d7e8f9g0h1i2j3k4l5m]
  OrdersFunction:
    Type: AWS::Serverless::Function
    Properties:
      Handler: app.handler
      CodeUri: src/
      Environment: { Variables: { TABLE: !Ref OrdersTable } }
      Policies: [{ DynamoDBCrudPolicy: { TableName: !Ref OrdersTable } }]
      Events:
        Create: { Type: HttpApi, Properties: { ApiId: !Ref HttpApi, Path: /orders, Method: POST } }
        List: { Type: HttpApi, Properties: { ApiId: !Ref HttpApi, Path: /orders, Method: GET } }
```

<Mistakes>

<Mistake title="Doing everything inside the request">

<Wrong>

```text
POST /orders writes the order, renders a PDF, calls the SMS provider and emails the customer — 6 s and fragile.
```

</Wrong>

<Right>

```text
Write the order and publish an event; return 201. Invoice, SMS and email run asynchronously with retries.
```

</Right>

</Mistake>

<Mistake title="Over-broad function permissions">

<Wrong>

```yaml
Policies: [AmazonDynamoDBFullAccess]      # every table in the account
```

</Wrong>

<Right>

```yaml
Policies: [{ DynamoDBCrudPolicy: { TableName: !Ref OrdersTable } }]
```

</Right>

</Mistake>

<InterviewQA>

<QA q="Describe a serverless REST API on AWS.">

API Gateway (HTTP API) exposes routes with a Cognito/JWT authorizer, throttling and a custom domain; each route invokes a Lambda function with a least-privilege execution role; data lives in DynamoDB designed around access patterns; asynchronous work goes through SQS or EventBridge to other functions; files use S3 presigned URLs; everything is defined in SAM or CDK and monitored with CloudWatch and X-Ray.

</QA>

<QA q="What are the trade-offs of serverless compared with containers?">

Serverless removes server management, scales automatically and is very cheap at low or spiky traffic, but has cold starts, execution time limits, per-request costs that can exceed containers at high steady load, vendor-specific patterns and harder local testing. Containers give more control, long-running processes and predictable cost at scale but need capacity and deployment management.

</QA>

<QA q="How do you test Lambda functions?">

Keep business logic in plain functions with unit tests; test handlers by calling them with sample API Gateway/SQS events; mock AWS services with moto or local emulators (DynamoDB Local, SAM local invoke); and run integration tests against a deployed dev stack.

</QA>

<CheatSheet>

| Layer | Choice |
| --- | --- |
| HTTPS + auth | API Gateway HTTP API + Cognito JWT authorizer |
| Code | Lambda (Python, arm64), init outside the handler |
| Data | DynamoDB on-demand, single-table keys |
| Async | EventBridge / SQS → Lambda (DLQ) |
| Files | S3 presigned URLs |
| IaC | SAM (`sam build`, `sam deploy`) or CDK |
| Permissions | SAM policy templates (`DynamoDBCrudPolicy`) |
| Observability | CloudWatch Logs/metrics, X-Ray, Powertools |
| Gotchas | cold starts · 29 s / 15 min · Decimal · cost at steady high load |

</CheatSheet>
