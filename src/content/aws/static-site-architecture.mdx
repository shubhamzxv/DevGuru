<Analogy>

A **printed brochure distributed by a courier network**. The brochure is printed once (the build), the master copies sit in a locked storeroom (private S3), and couriers in every city (CloudFront) keep copies to hand out instantly. When you print a new edition, you replace the cover page (index.html) everywhere, and the cover tells readers which new inside pages to pick up.

</Analogy>

## Simple explanation

**The pieces and why each is there**

| Piece | Setting | Why |
| --- | --- | --- |
| **S3 bucket** | private, Block Public Access ON, versioning | stores `dist/`; never public |
| **CloudFront distribution** | origin = bucket with **OAC**, default root object `index.html` | fast global delivery, HTTPS, only way in |
| **Bucket policy** | allow `cloudfront.amazonaws.com` with `AWS:SourceArn` = the distribution | locks the bucket to this distribution |
| **ACM certificate** | in **us-east-1**, DNS-validated | HTTPS on `shop.example.com` |
| **Route 53** | alias A/AAAA `shop.example.com` → distribution | apex domain works |
| **SPA fallback** | 403/404 → `/index.html`, status 200 (or a CloudFront Function) | `/products/7` loads the app, not an error |
| **Caching** | hashed `assets/*` = 1 year immutable; `index.html` = no-cache | fast + instant updates |
| **Headers** | response headers policy: HSTS, CSP, X-Content-Type-Options, frame options | security |
| **Optional** | WAF, geo restriction, logs, `/api/*` behavior to an ALB/API Gateway | protection, one domain |

**Deploy pipeline (GitHub Actions)**

1. `npm ci && npm test && npm run build`
2. Assume an AWS role with **OIDC** (no stored keys)
3. `aws s3 sync dist/ s3://bucket --delete` with cache headers (assets long, `index.html` no-cache)
4. `aws cloudfront create-invalidation --paths "/index.html"`

**Cost**: a small site costs a few rupees to a few dollars a month (S3 storage + CloudFront transfer, which has a free monthly allowance).

**Why not S3 static website hosting alone?** It is HTTP-only, needs a public bucket, and has no CDN. Use it only for redirects or quick experiments.

## Code example

GitHub Actions deploy job:

```yaml
name: deploy
on: { push: { branches: [main] } }
permissions: { id-token: write, contents: read }
jobs:
  deploy:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-node@v4
        with: { node-version: 22, cache: npm }
      - run: npm ci && npm test && npm run build
      - uses: aws-actions/configure-aws-credentials@v4
        with:
          role-to-assume: arn:aws:iam::123456789012:role/github-deploy-frontend
          aws-region: ap-south-1
      - run: |
          aws s3 sync dist/ s3://shop-frontend --delete --exclude index.html \
            --cache-control "public,max-age=31536000,immutable"
          aws s3 cp dist/index.html s3://shop-frontend/index.html --cache-control "no-cache"
          aws cloudfront create-invalidation --distribution-id E2ABCDEF123456 --paths "/index.html"
```

```output
upload: dist/assets/index-3f9a1c.js to s3://shop-frontend/assets/index-3f9a1c.js
upload: dist/assets/index-8b2e4d.css to s3://shop-frontend/assets/index-8b2e4d.css
delete: s3://shop-frontend/assets/index-1a0b9c.js
upload: dist/index.html to s3://shop-frontend/index.html
{ "Invalidation": { "Id": "I2K9...", "Status": "InProgress" } }
```

Old hashed files are deleted by `--delete`; to avoid errors for users with an open old tab, you can keep previous assets for a while (sync without `--delete` and clean up with a lifecycle rule).

<Mistakes>

<Mistake title="Public website bucket">

<Wrong>

```text
S3 static website hosting + public-read bucket policy, http:// only, no CDN.
```

</Wrong>

<Right>

```text
Private bucket + CloudFront (OAC) + ACM HTTPS + Route 53 alias.
```

</Right>

</Mistake>

<Mistake title="Long-lived AWS keys in CI">

<Wrong>

```text
AWS_ACCESS_KEY_ID / AWS_SECRET_ACCESS_KEY of an admin user saved as GitHub secrets.
```

</Wrong>

<Right>

```text
GitHub OIDC → assume a role that may only s3:PutObject/DeleteObject on this bucket and create invalidations.
```

</Right>

</Mistake>

<InterviewQA>

<QA q="How would you host a React single-page application on AWS?">

Build it in CI, upload the output to a private S3 bucket, serve it through CloudFront with Origin Access Control and a bucket policy restricted to the distribution, attach an ACM certificate from us-east-1 and a Route 53 alias, configure SPA fallback to index.html, cache hashed assets long and index.html briefly, add security headers (and WAF if needed), and invalidate index.html on each deploy. Amplify Hosting is the managed alternative.

</QA>

<QA q="Why not just enable S3 static website hosting?">

Website endpoints support only HTTP, require a public bucket, and lack CDN caching, custom TLS, WAF and edge features. CloudFront in front of a private bucket provides HTTPS, global performance and better security.

</QA>

<QA q="How do you deploy without users seeing stale files?">

Use content-hashed asset names so new builds never overwrite old URLs, set long immutable caching on them, keep index.html no-cache or short TTL, and invalidate index.html after uploading. Keep old assets for a while so open tabs do not break.

</QA>
