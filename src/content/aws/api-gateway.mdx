<Analogy>

The **reception desk of an office tower**. Visitors never walk straight into departments: reception checks their ID badge (authorizer), sends them to the right floor (route → integration), limits how many people from one company may enter per minute (throttling), and keeps a visitor log (access logs).

</Analogy>

## Simple explanation

| Type | When |
| --- | --- |
| **HTTP API** | most new APIs: Lambda/HTTP backends, JWT auth, CORS built in, lower cost and latency |
| **REST API** | need API keys + usage plans, request validation, transformations, caching, WAF, private endpoints, direct AWS service integrations |
| **WebSocket API** | chat, live dashboards: `$connect`, `$disconnect`, custom routes |

**Pieces**

| Piece | Example |
| --- | --- |
| **Route** | `POST /orders`, `GET /orders/{id}`, `$default` |
| **Integration** | Lambda proxy, HTTP proxy to an ALB/URL, private integration via VPC link |
| **Authorizer** | JWT (Cognito, Auth0), IAM (SigV4), Lambda authorizer (custom tokens) |
| **Stage** | `dev`, `prod` with stage variables; auto-deploy for HTTP APIs |
| **Custom domain** | `api.shop.example.com` with an ACM certificate + base path mapping `/v1` |
| **Throttling** | default account limit (10,000 rps); per-route limits, usage plans |
| **CORS** | allowed origins, methods, headers |
| **Logging** | access logs + execution logs to CloudWatch; X-Ray tracing |

**Lambda proxy event (HTTP API, payload v2)** your function receives: `routeKey`, `rawPath`, `headers`, `queryStringParameters`, `pathParameters`, `body` (string, maybe base64), `requestContext.authorizer.jwt.claims`. It returns `{statusCode, headers, body}`.

Limits to remember: **29-second integration timeout** by default (REST API regional can request more), 10 MB payload. Long work → return 202 and process asynchronously (SQS, Step Functions).

Alternatives: **Lambda function URLs** (simple single-function HTTPS endpoint), **ALB** with Lambda targets, **AppSync** for GraphQL.

## Code example

```bash
# Create an HTTP API that sends every request to a Lambda function (quick create)
aws apigatewayv2 create-api --name shop-api --protocol-type HTTP \
  --target arn:aws:lambda:ap-south-1:123456789012:function:order-total
aws lambda add-permission --function-name order-total --statement-id apigw \
  --action lambda:InvokeFunction --principal apigateway.amazonaws.com \
  --source-arn "arn:aws:execute-api:ap-south-1:123456789012:a1b2c3d4e5/*"

curl -s -X POST https://a1b2c3d4e5.execute-api.ap-south-1.amazonaws.com/orders/total \
  -H "Content-Type: application/json" -d '{"items":[{"price":450,"qty":1},{"price":199,"qty":2}]}'
```

```output
{"items": 2, "total": 848}
```

Reading path parameters and JWT claims in the handler:

```python
def lambda_handler(event, context):
    order_id = event["pathParameters"]["id"]                                  # GET /orders/{id}
    user = event["requestContext"]["authorizer"]["jwt"]["claims"]["sub"]       # from the JWT authorizer
    return {"statusCode": 200, "body": json.dumps({"order": order_id, "user": user})}
```

A FastAPI app can sit behind API Gateway on Lambda with **Mangum** (`handler = Mangum(app)`).

<Mistakes>

<Mistake title="Long synchronous work behind API Gateway">

<Wrong>

```text
POST /reports runs a 2-minute export in Lambda → API Gateway returns 504 after ~29 seconds.
```

</Wrong>

<Right>

```text
POST /reports puts a job on SQS and returns 202 + job id; the client polls GET /reports/{id} or gets a WebSocket/email.
```

</Right>

</Mistake>

<Mistake title="Checking tokens yourself in every function">

<Wrong>

```python
def lambda_handler(event, context):
    token = event["headers"]["authorization"]   # hand-written JWT checks copied into 20 functions
```

</Wrong>

<Right>

```text
A JWT/Cognito authorizer on the routes; functions read verified claims from requestContext.
```

</Right>

</Mistake>

<InterviewQA>

<QA q="What is the difference between API Gateway HTTP APIs and REST APIs?">

HTTP APIs are newer, cheaper and faster, supporting Lambda and HTTP integrations, JWT authorizers, CORS and auto-deploy. REST APIs offer more features: API keys and usage plans, request validation and mapping templates, response caching, WAF integration, private APIs and direct AWS service integrations.

</QA>

<QA q="How can you secure an API Gateway endpoint?">

Authorizers (JWT/Cognito, IAM SigV4, Lambda authorizers), resource policies or private APIs reachable only from a VPC, WAF rules (REST), throttling and usage plans with API keys for partners, mutual TLS on custom domains, and least-privilege permissions on the integrations.

</QA>

<QA q="How does API Gateway integrate with Lambda?">

With a Lambda proxy integration, API Gateway passes the full HTTP request as an event (method, path, headers, query, body, auth context) and invokes the function synchronously; the function returns statusCode, headers and body which are mapped to the HTTP response. Lambda needs a resource-based permission allowing apigateway.amazonaws.com to invoke it.

</QA>

<CheatSheet>

| Need | Feature |
| --- | --- |
| Lambda API | HTTP API + Lambda proxy |
| Auth | JWT / Cognito · IAM · Lambda authorizer |
| Domain | custom domain + ACM + base path `/v1` |
| Limits | throttling per route · usage plans (REST) |
| Private backend | VPC link → ALB/NLB |
| Real time | WebSocket API |
| Logs | access logs → CloudWatch · X-Ray |
| Timeout | ~29 s → long jobs via SQS + 202 |
| Lambda permission | `aws lambda add-permission --principal apigateway.amazonaws.com` |

</CheatSheet>
