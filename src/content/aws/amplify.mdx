<Analogy>

A **printing press with a delivery service included**. You hand over your manuscript (Git repository) once. Every time you edit it (push), the press prints a new edition (build) and delivers it to every bookshop in the world (CDN). Draft chapters (other branches, pull requests) get their own preview copies for reviewers.

</Analogy>

## Simple explanation

**What Amplify Hosting does for you**

| Feature | Detail |
| --- | --- |
| CI/CD | connect GitHub/GitLab/Bitbucket/CodeCommit; build on push |
| Hosting | global CDN, HTTPS, atomic deploys, instant rollback to a previous build |
| Branches | `main` → production, `dev` → `dev.xxxx.amplifyapp.com` |
| PR previews | a temporary URL per pull request |
| Custom domain | `shop.example.com` with a free certificate (Route 53 or other DNS) |
| Rewrites/redirects | SPA fallback, `www` → apex, `/old` → `/new` |
| Env variables | per branch, e.g. `VITE_API_URL` |
| SSR | Next.js server rendering supported |
| Access control | password-protect a branch |

**Build settings** live in `amplify.yml` (or the console):

```yaml
version: 1
frontend:
  phases:
    preBuild:
      commands:
        - npm ci
    build:
      commands:
        - npm run build
  artifacts:
    baseDirectory: dist
    files:
      - "**/*"
  cache:
    paths:
      - node_modules/**/*
```

**SPA rewrite** (React Router): source `</^[^.]+$|\.(?!(css|gif|ico|jpg|js|png|txt|svg|woff|woff2|ttf|map|json|webp)$)([^.]+$)/>` → target `/index.html`, type `200 (Rewrite)`.

**Amplify Hosting vs S3 + CloudFront**

| | Amplify Hosting | S3 + CloudFront (DIY) |
| --- | --- | --- |
| Setup | minutes | more steps (bucket, OAC, distribution, cert, CI) |
| CI/CD, previews | built in | build yourself (GitHub Actions) |
| Control | less (headers via custom headers file) | full (behaviors, WAF, functions, policies) |
| Cost | build minutes + hosting | usually very low |

The wider "Amplify" also has a backend framework (Gen 2: auth with Cognito, data with AppSync/DynamoDB, storage) and UI libraries; Hosting can be used alone.

## Code example

```bash
# Create an app connected to GitHub and deploy the main branch (one-time; the console wizard does the same)
aws amplify create-app --name shop-frontend --repository https://github.com/shubham/shop-frontend \
  --access-token "$GITHUB_TOKEN" --platform WEB
aws amplify create-branch --app-id d1a2b3c4d5e6f7 --branch-name main --stage PRODUCTION
aws amplify start-job --app-id d1a2b3c4d5e6f7 --branch-name main --job-type RELEASE
aws amplify list-jobs --app-id d1a2b3c4d5e6f7 --branch-name main --max-items 1 \
  --query "jobSummaries[0].{id:jobId,status:status,commit:commitId}"
```

```output
{
    "id": "1",
    "status": "SUCCEED",
    "commit": "7c8d9e0"
}
```

The site is live at `https://main.d1a2b3c4d5e6f7.amplifyapp.com`; after that, every `git push` to `main` starts a new job automatically.

<Mistakes>

<Mistake title="Wrong output folder">

<Wrong>

```yaml
artifacts:
  baseDirectory: build      # Vite outputs to dist/ → deploy succeeds but shows an error page
```

</Wrong>

<Right>

```yaml
artifacts:
  baseDirectory: dist       # match your tool: Vite dist/, Create React App build/, Next.js .next
```

</Right>

</Mistake>

<Mistake title="Secrets in frontend environment variables">

<Wrong>

```text
VITE_STRIPE_SECRET_KEY=sk_live_... → bundled into public JavaScript for everyone to read.
```

</Wrong>

<Right>

```text
Only public values (API URL, publishable keys) in frontend env vars; secrets stay on the backend.
```

</Right>

</Mistake>

<InterviewQA>

<QA q="What is AWS Amplify Hosting?">

A managed service that connects to a Git repository, builds a web frontend on each push using build settings, and serves it from a global CDN with HTTPS, custom domains, branch deployments, pull-request previews, redirects, environment variables and rollbacks, including SSR support for frameworks like Next.js.

</QA>

<QA q="When would you choose S3 + CloudFront instead of Amplify Hosting?">

When you need full control over CloudFront behaviors, cache policies, WAF, edge functions, multiple origins or infrastructure defined in your own IaC and CI pipeline, or want to minimise cost at scale. Amplify is faster to set up and includes CI/CD and previews.

</QA>

<QA q="How do you make client-side routes work on a static host?">

Configure a rewrite so any path that is not a real file returns index.html with status 200 (Amplify rewrite rule, or CloudFront custom error responses / a CloudFront Function), letting the SPA router handle the URL.

</QA>

<CheatSheet>

| Task | How |
| --- | --- |
| Connect repo | console wizard / `aws amplify create-app` |
| Build config | `amplify.yml` (preBuild, build, artifacts.baseDirectory) |
| Vite output | `dist` |
| Branch env | `create-branch` + env vars per branch |
| PR previews | enable in app settings |
| Domain | custom domain + automatic certificate |
| SPA | rewrite → `/index.html` (200) |
| Roll back | redeploy an earlier build |
