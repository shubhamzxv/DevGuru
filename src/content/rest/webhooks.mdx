<Analogy>

Waiting for a parcel, you could phone the courier every 10 minutes: "Has it arrived?" That is **polling**, tiring for both of you.

Or you give them your number and they **message you** when it is delivered. That is a **webhook**: you give a service your URL, and it calls you when the event happens.

</Analogy>

## Simple explanation

A **webhook** is a reverse API call:

1. You register a URL with a provider, such as `https://api.myshop.in/webhooks/razorpay`, and choose events (`payment.captured`, `refund.created`)
2. When the event happens, the provider sends an **HTTP POST** with a JSON body describing it
3. Your endpoint checks it, records it, and replies **2xx quickly**

Common examples: payment gateways (Razorpay, Stripe) confirming payments, GitHub calling CI on every push, Twilio delivering SMS status, Shopify order events.

Webhooks are delivered over the internet by someone else's system, so build the receiver defensively:

- **Verify the signature**: the provider signs the raw body with a shared secret (HMAC-SHA256) and sends it in a header such as `X-Razorpay-Signature`. Recompute it and compare with `hmac.compare_digest`. Without this, anyone could POST a fake "payment captured"
- **Respond fast** (within a few seconds): save the event and return 200, then do the real work in a background job or queue. Slow responses are treated as failures
- **Expect retries and duplicates**: providers retry when you fail or time out, and may deliver an event more than once. Store the **event id** and ignore repeats (idempotency)
- **Do not rely on order**: `payment.captured` may arrive before `order.created`. Check current state, or fetch the latest object from the provider's API
- **Use HTTPS**, and optionally a timestamp in the signature to reject old replayed requests
- Keep a way to **replay** missed events (most providers have a dashboard or an events API)

## Code example

A webhook receiver that verifies the signature and ignores duplicates:

```python
import hashlib, hmac, json
from fastapi import FastAPI, Header, HTTPException, Request

app = FastAPI()
WEBHOOK_SECRET = b"whsec_from_the_provider_dashboard"
seen_events: set[str] = set()            # a DB table with a UNIQUE column in real life
jobs: list[dict] = []                    # stand-in for a queue

@app.post("/webhooks/payments")
async def payment_webhook(request: Request, x_signature: str = Header(...)):
    raw = await request.body()                                    # sign the RAW bytes
    expected = hmac.new(WEBHOOK_SECRET, raw, hashlib.sha256).hexdigest()
    if not hmac.compare_digest(expected, x_signature):
        raise HTTPException(status_code=401, detail="Bad signature")
    event = json.loads(raw)
    if event["id"] in seen_events:
        return {"status": "duplicate ignored"}
    seen_events.add(event["id"])
    jobs.append(event)                                            # process later, reply now
    return {"status": "accepted"}
```

```python
from fastapi.testclient import TestClient

print(c.post("/webhooks/payments", content=body, headers={"X-Signature": "fake"}).status_code)
```

<Mistakes>

<Mistake title="Trusting the webhook body without a signature check">

<Wrong>

```python
@app.post("/webhooks/payments")
def hook(event: dict):
    mark_order_paid(event["order_id"])        # anyone can POST this and get free goods
```

</Wrong>

<Right>

```python
expected = hmac.new(SECRET, raw_body, hashlib.sha256).hexdigest()
if not hmac.compare_digest(expected, request.headers["X-Signature"]):
    raise HTTPException(401)
```

</Right>

Webhook URLs are public. Only the signature proves the provider sent it.

</Mistake>

<Mistake title="Doing slow work before answering">

<Wrong>

```python
@app.post("/webhooks/payments")
def hook(event: dict):
    generate_invoice_pdf(event)               # 20 seconds
    send_email(event)
    return {"ok": True}                       # provider timed out and will retry: duplicates
```

</Wrong>

<Right>

```python
@app.post("/webhooks/payments")
def hook(event: dict):
    queue.enqueue("process_payment", event)   # milliseconds
    return {"ok": True}
```

</Right>

Answer within the provider's timeout and move the heavy work to a background worker.

</Mistake>

<InterviewQA>

<QA q="What is a webhook, and how is it different from polling?">

A webhook is an HTTP callback: a provider sends a POST request to a URL you registered when an event occurs. With polling, the client repeatedly asks the provider whether something changed, wasting requests and adding delay. Webhooks deliver events in near real time with far fewer calls.

</QA>

<QA q="How do you secure and make a webhook endpoint reliable?">

Verify an HMAC signature over the raw body with a shared secret (and a timestamp to stop replays), serve it only over HTTPS, respond 2xx quickly and process asynchronously, store event ids to ignore duplicates, tolerate out-of-order delivery, log every event, and support replaying missed events.

</QA>

<QA q="What happens if your webhook endpoint is down?">

Providers retry with backoff for a period (hours to days, depending on the provider) and may disable the endpoint after repeated failures. Missed events can usually be replayed from the provider's dashboard or fetched through its events API; idempotent handling makes the replays safe.

</QA>

<CheatSheet>

| Rule | How |
| --- | --- |
| Authenticate | HMAC-SHA256 of the raw body, `hmac.compare_digest` |
| Stop replays | signed timestamp, reject old ones |
| Be fast | save + enqueue, answer 2xx in under a few seconds |
| Duplicates | unique event id table |
| Order | do not assume it; re-fetch state if needed |
| Transport | HTTPS only |
| Recovery | provider retries + replay from dashboard / events API |

</CheatSheet>
