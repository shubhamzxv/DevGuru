A restaurant needs a **proper kitchen** (Gunicorn with several cooks, the workers), a **front counter** (Nginx) that takes orders, serves ready items (static files) and handles the crowd, and a **health inspector** checking regularly (health checks).

## Simple explanation

A typical production setup:

```text
Users ──HTTPS──> Nginx / AWS ALB ──> Gunicorn (4 workers) ──> Flask app ──> PostgreSQL, Redis
```

**Gunicorn** is a WSGI server: `gunicorn -w 4 -b 0.0.0.0:8000 "myapp:create_app()"`

- `-w`: number of **worker processes**; a common start is **2 × CPU cores + 1**
- `--threads 4`: threads per worker, helps I/O-heavy apps
- `--timeout 30`: kills a worker stuck longer than this
- `app:app` means "module `app`, variable `app`"; `"myapp:create_app()"` calls a factory
- On Windows, Gunicorn does not run; use **Waitress** (`waitress-serve --port=8000 app:app`)

**Nginx** in front: HTTPS (TLS), gzip, serves `/static/` directly, buffers slow clients, forwards the rest to Gunicorn. Add **ProxyFix** in Flask so it trusts `X-Forwarded-*` headers.

**Production checklist**

| Item | How |
| --- | --- |
| Debug off | never `--debug`; `DEBUG=False` |
| Secrets | `SECRET_KEY`, DB URL from environment variables or AWS Secrets Manager |
| Database | PostgreSQL/MySQL, not SQLite for multi-server apps; `flask db upgrade` on each deploy |
| Cookies | `SESSION_COOKIE_SECURE=True`, `HTTPONLY`, `SAMESITE="Lax"` |
| Logs | to stdout/stderr (Docker, CloudWatch collect them) |
| Health check | a `/health` route the load balancer calls |
| Static files | Nginx or S3 + CloudFront |
| Errors | Sentry or similar |

**Docker** packs the app with its Python version and packages, so it runs the same on your laptop, in CI and on AWS (ECS, App Runner, EC2, Elastic Beanstalk).

## Code example

A `/health` route and production config loaded from environment variables:

```python
import os
from flask import Flask

def create_app():
    app = Flask(__name__)
    app.config.update(
        DEBUG=False,
        SECRET_KEY=os.environ.get("SECRET_KEY"),             # read at startup, never hard-coded
        SQLALCHEMY_DATABASE_URI=os.environ.get("DATABASE_URL"),
        SESSION_COOKIE_SECURE=True,
        SESSION_COOKIE_HTTPONLY=True,
        SESSION_COOKIE_SAMESITE="Lax",
    )
    if not app.config["SECRET_KEY"]:
        raise RuntimeError("SECRET_KEY is not set")          # fail fast, not with broken sessions later

    @app.get("/health")
    def health():
        return {"status": "ok"}

    return app

try:
    create_app()
except RuntimeError as e:
    print("Startup check:", e)

os.environ["SECRET_KEY"] = "from-the-environment"            # set by Docker / ECS / systemd
os.environ["DATABASE_URL"] = "postgresql://app@db:5432/app"
app = create_app()
print(app.test_client().get("/health").json, "DEBUG:", app.config["DEBUG"])
print("DB:", app.config["SQLALCHEMY_DATABASE_URI"])
```

```output
Startup check: SECRET_KEY is not set
{'status': 'ok'} DEBUG: False
DB: postgresql://app@db:5432/app
```

Gunicorn worker count for a machine:

```python
for cores in (1, 2, 4, 8):        # os.cpu_count() gives your machine's cores
    print(f"{cores} cores -> gunicorn -w {2 * cores + 1}")
```

```output
1 cores -> gunicorn -w 3
2 cores -> gunicorn -w 5
4 cores -> gunicorn -w 9
8 cores -> gunicorn -w 17
```

from werkzeug.middleware.proxy_fix import ProxyFix
from myapp import create_app

app = create_app()
app.wsgi_app = ProxyFix(app.wsgi_app, x_for=1, x_proto=1)   # trust Nginx headers

<Mistakes>

<Mistake title="Running flask run in production">

<Wrong>

```bash
nohup flask --app app run --host 0.0.0.0 --port 80 &
```

</Wrong>

<Right>

```bash
gunicorn -w 4 -b 127.0.0.1:8000 "myapp:create_app()"     # behind Nginx with HTTPS
```

</Right>

The Werkzeug dev server warns "Do not use it in a production deployment". It is not built for security or load.

</Mistake>

<Mistake title="Using SQLite with several servers or containers">

<Wrong>

```python
SQLALCHEMY_DATABASE_URI = "sqlite:///app.db"   # each container has its own file; data lost on redeploy
```

</Wrong>

<Right>

```python
SQLALCHEMY_DATABASE_URI = os.environ["DATABASE_URL"]   # PostgreSQL on RDS, for example
```

</Right>

SQLite is a single file on one disk. Use a database server for anything that scales out.

</Mistake>

<InterviewQA>

<QA q="How do you deploy a Flask app to production?">

Run it on a WSGI server such as Gunicorn (several workers) behind Nginx or a cloud load balancer that handles HTTPS and static files. Use environment variables for config and secrets, PostgreSQL, migrations on deploy, logs to stdout, a health-check route, and usually Docker on ECS, App Runner, EC2 or Kubernetes.

</QA>

<QA q="How many Gunicorn workers should you use?">

A common starting point is 2 × CPU cores + 1, then tune with load tests. CPU-heavy apps want about one worker per core; I/O-heavy apps can add `--threads` or use gevent workers.

</QA>

<QA q="Why put Nginx in front of Gunicorn?">

Nginx terminates TLS, serves static files fast, compresses responses, buffers slow clients so Gunicorn workers are not tied up, limits request sizes and rates, and can balance across several app servers.

</QA>

<QA q="What is the difference between WSGI and ASGI?">

WSGI is the synchronous Python standard: one request per worker thread at a time (Flask, Django classic). ASGI is the async standard that supports WebSockets and many concurrent connections per worker (FastAPI, Starlette, Django channels, Quart).

</QA>
