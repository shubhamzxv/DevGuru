<Analogy>

A **JWT** is like a **metro smart card** with your trip details printed and **sealed**. The gate does not call head office for every passenger; it checks the seal and the expiry date on the card itself. An **access token** is a day pass (short). A **refresh token** is the card you show at the counter to get a new day pass.

</Analogy>

## Simple explanation

A **JWT** (JSON Web Token) has three base64 parts: `header.payload.signature`.

- **Payload** (claims): `sub` (the user id), `exp` (expiry), `iat` (issued at), `jti` (token id), and your own claims such as `role`
- **Signature**: made with the server's secret key. Anyone can **read** the payload, but nobody can **change** it without the key
- So: no passwords or secrets inside the token

**Flask-JWT-Extended** (`pip install flask-jwt-extended`):

| Piece | Job |
| --- | --- |
| `JWTManager(app)` + `JWT_SECRET_KEY` | set up |
| `create_access_token(identity=str(user.id))` | short-lived token (default **15 minutes**) |
| `create_refresh_token(identity=...)` | long-lived token (default **30 days**) to get new access tokens |
| `@jwt_required()` | route needs a valid access token |
| `@jwt_required(refresh=True)` | route needs a refresh token |
| `get_jwt_identity()` | the `sub` of the token |
| `get_jwt()` | all claims (role, jti, exp…) |
| `additional_claims={...}` | add data such as the role |
| `@jwt.token_in_blocklist_loader` | check revoked tokens (logout) |

The client sends the token in the header: **`Authorization: Bearer <token>`**.

If the token is missing, expired or revoked, Flask-JWT-Extended answers **401**. If it is broken, has a bad signature or is the wrong type (a refresh token on a normal route), it answers **422**.

**Identity must be a string** (the JWT standard says `sub` is a string), so use `identity=str(user.id)`.

**Logout and revoking**: a JWT is valid until it expires. To log out early, store its `jti` in a **blocklist** (usually **Redis**, with the same expiry) and check it on each request. Short access-token lifetimes keep the risk small.

Where to store tokens in a browser: an **HttpOnly cookie** (Flask-JWT-Extended supports `JWT_TOKEN_LOCATION=["cookies"]` with CSRF protection) is safer against XSS than localStorage.

## Code example

Login, a protected route, a role check, refresh and logout:

```python
from datetime import timedelta
from flask import Flask, request
from flask_jwt_extended import (JWTManager, create_access_token, create_refresh_token,
                                get_jwt, get_jwt_identity, jwt_required)
from werkzeug.security import check_password_hash, generate_password_hash

app = Flask(__name__)
app.config["JWT_SECRET_KEY"] = "dev-only-secret-at-least-32-bytes-long!"
app.config["JWT_ACCESS_TOKEN_EXPIRES"] = timedelta(minutes=15)
jwt = JWTManager(app)

USERS = {"asha": {"id": 1, "hash": generate_password_hash("MyPass@123"), "role": "admin"}}
BLOCKLIST = set()                                  # use Redis in production

@jwt.token_in_blocklist_loader
def is_revoked(jwt_header, jwt_payload):
    return jwt_payload["jti"] in BLOCKLIST

@app.post("/login")
def login():
    data = request.get_json()
    user = USERS.get(data.get("username"))
    if not user or not check_password_hash(user["hash"], data.get("password", "")):
        return {"msg": "Wrong username or password"}, 401
    claims = {"role": user["role"]}
    return {"access_token": create_access_token(identity=str(user["id"]), additional_claims=claims),
            "refresh_token": create_refresh_token(identity=str(user["id"]))}

@app.get("/me")
@jwt_required()
def me():
    return {"user_id": get_jwt_identity(), "role": get_jwt()["role"]}

@app.get("/admin")
@jwt_required()
def admin():
    if get_jwt().get("role") != "admin":
        return {"msg": "Admins only"}, 403
    return {"msg": "Welcome, admin"}

@app.post("/refresh")
@jwt_required(refresh=True)
def refresh():
    return {"access_token": create_access_token(identity=get_jwt_identity())}

@app.post("/logout")
@jwt_required()
def logout():
    BLOCKLIST.add(get_jwt()["jti"])
    return {"msg": "Token revoked"}

c = app.test_client()
print(c.get("/me").status_code, c.get("/me").json)
tokens = c.post("/login", json={"username": "asha", "password": "MyPass@123"}).json
access, refresh_token = tokens["access_token"], tokens["refresh_token"]
print("parts in token:", len(access.split(".")))
auth = {"Authorization": f"Bearer {access}"}
print(c.get("/me", headers=auth).json)
print(c.get("/admin", headers=auth).json)
r = c.post("/refresh", headers={"Authorization": f"Bearer {refresh_token}"})
print("refresh:", r.status_code, "access_token" in r.json)
print("refresh token on /me:", c.get("/me", headers={"Authorization": f"Bearer {refresh_token}"}).status_code)
print(c.post("/logout", headers=auth).json)
print(c.get("/me", headers=auth).status_code, c.get("/me", headers=auth).json)
```

```output
401 {'msg': 'Missing Authorization Header'}
parts in token: 3
{'role': 'admin', 'user_id': '1'}
{'msg': 'Welcome, admin'}
refresh: 200 True
refresh token on /me: 422
{'msg': 'Token revoked'}
401 {'msg': 'Token has been revoked'}
```

Anyone can read a JWT payload, but changing it breaks the signature:

```python
import base64, json
from flask import Flask
from flask_jwt_extended import JWTManager, create_access_token, jwt_required, get_jwt_identity

app = Flask(__name__)
app.config["JWT_SECRET_KEY"] = "dev-only-secret-at-least-32-bytes-long!"
JWTManager(app)

@app.get("/me")
@jwt_required()
def me():
    return {"user": get_jwt_identity()}

with app.app_context():
    token = create_access_token(identity="7")

header, payload, signature = token.split(".")
claims = json.loads(base64.urlsafe_b64decode(payload + "=="))
print({k: claims[k] for k in ("sub", "type", "fresh")}, "exp" in claims, "jti" in claims)

claims["sub"] = "1"                                   # pretend to be user 1
forged_payload = base64.urlsafe_b64encode(json.dumps(claims).encode()).decode().rstrip("=")
forged = f"{header}.{forged_payload}.{signature}"
r = app.test_client().get("/me", headers={"Authorization": f"Bearer {forged}"})
print(r.status_code, r.json)
```

```output
{'sub': '7', 'type': 'access', 'fresh': False} True True
422 {'msg': 'Signature verification failed'}
```

<Mistakes>

<Mistake title="Putting secrets in the token">

<Wrong>

```python
create_access_token(identity=str(user.id), additional_claims={"password": pw, "pan": user.pan})
```

</Wrong>

<Right>

```python
create_access_token(identity=str(user.id), additional_claims={"role": user.role})
```

</Right>

The payload is only base64 encoded. Anyone holding the token can read every claim.

</Mistake>

<Mistake title="Very long access tokens with no way to revoke">

<Wrong>

```python
app.config["JWT_ACCESS_TOKEN_EXPIRES"] = timedelta(days=365)   # a stolen token works for a year
```

</Wrong>

<Right>

```python
app.config["JWT_ACCESS_TOKEN_EXPIRES"] = timedelta(minutes=15)
app.config["JWT_REFRESH_TOKEN_EXPIRES"] = timedelta(days=30)
# + blocklist (Redis) checked in token_in_blocklist_loader
```

</Right>

Keep access tokens short, use refresh tokens for new ones, and keep a blocklist for logout.

</Mistake>

<InterviewQA>

<QA q="What is the structure of a JWT?">

Three base64url parts joined by dots: a header (algorithm, type), a payload of claims (`sub`, `exp`, `iat`, `jti`, custom ones) and a signature over the first two made with the secret (HS256) or a private key (RS256). The signature proves the token was not changed.

</QA>

<QA q="Why use access and refresh tokens?">

The access token is short-lived and sent with every request, so a stolen one is useful only briefly. The refresh token lives longer, is sent only to the refresh endpoint, and gets new access tokens without asking for the password again.

</QA>

<QA q="How do you log out a user with JWT?">

JWTs are stateless, so you revoke them by storing their `jti` in a blocklist (Redis with a TTL equal to the token's remaining life) and rejecting listed tokens in `token_in_blocklist_loader`. The client also deletes its tokens.

</QA>

<QA q="HS256 vs RS256?">

HS256 uses one shared secret to sign and verify, fine when one service does both. RS256 signs with a private key and verifies with a public key, so many services can verify tokens without being able to create them.

</QA>
