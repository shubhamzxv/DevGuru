<Analogy>

A restaurant: the **store room** holds the ingredients (Model), the **chef** decides what to cook for each order (View), and the **plating** makes it look right on the table (Template). The **waiter** who takes the order to the right chef is the URL dispatcher.

</Analogy>

## Simple explanation

```text
Browser ──GET /products/──> URLconf ──> View ──> Model (ORM) ──> Database
                                         │
                                         └──> Template ──> HTML response
```

| Part | Django file | Responsibility |
| --- | --- | --- |
| **Model** | `models.py` | data structure, database access, business rules close to the data |
| **View** | `views.py` | receive the request, fetch/change data, choose the response |
| **Template** | `templates/*.html` | presentation: HTML with `{{ variables }}` and `{% tags %}` |
| (URLconf) | `urls.py` | map URL patterns to views |

**MVT vs MVC**: in classic MVC the **Controller** handles input and the **View** is the presentation. Django's naming is shifted:

| MVC | Django MVT |
| --- | --- |
| Model | Model |
| Controller | View (+ URLconf, and the framework itself) |
| View | Template |

For a **JSON API** (Django REST Framework) the "template" is replaced by a **serializer** that turns models into JSON.

Where business logic goes: simple rules on the model (methods, managers), request handling in views, and complex multi-model workflows in a **service layer** (`services.py`) so views stay thin and logic is testable.

## Code example

```python
# models.py: data
class Product(models.Model):
    name = models.CharField(max_length=100)
    price = models.DecimalField(max_digits=8, decimal_places=2)
    stock = models.PositiveIntegerField(default=0)

# views.py: logic
def product_list(request):
    products = Product.active.select_related("category")
    q = request.GET.get("q")
    if q:
        products = products.filter(name__icontains=q)
    return render(request, "store/product_list.html", {"products": products, "q": q})

# urls.py: routing
urlpatterns = [path("", views.product_list, name="product-list")]
```

```html
<!-- templates/store/product_list.html: presentation -->
<h1>Products{% if q %} matching "{{ q }}"{% endif %}</h1>
<ul>
{% for product in products %}
  <li>{{ product.name }} ({{ product.category.name }}) ₹{{ product.price|floatformat:0 }}</li>
{% empty %}
  <li>No products found.</li>
{% endfor %}
</ul>
```

```output
GET /products/?q=cable  →  Products matching "cable" · USB Cable (Electronics) ₹199
```

<Mistakes>

<Mistake title="Fat views">

<Wrong>

```python
def checkout(request):
    # 150 lines: stock checks, price rules, payment call, emails, inventory updates...
```

</Wrong>

<Right>

```python
def checkout(request):
    order = services.place_order(user=request.user, cart=request.session["cart"])   # logic in a service
    return redirect("orders:detail", pk=order.pk)
```

</Right>

</Mistake>

<Mistake title="Queries inside templates">

<Wrong>

```html
{% for order in user.orders.all %}{% for item in order.items.all %}{{ item.product.name }}{% endfor %}{% endfor %}
<!-- N+1 queries hidden in the template -->
```

</Wrong>

<Right>

```python
orders = request.user.orders.prefetch_related("items__product")   # fetch in the view, then loop in the template
```

</Right>

</Mistake>

<InterviewQA>

<QA q="Explain Django's MVT architecture.">

The Model defines data and talks to the database through the ORM, the View contains the request-handling logic and decides what to return, and the Template renders the presentation. The URL dispatcher routes requests to views, so Django itself acts as the controller; MVT's View corresponds to MVC's Controller and the Template to MVC's View.

</QA>

<QA q="Where do you put business logic in Django?">

Small rules that belong to one model go in model methods, properties or custom managers/querysets; views stay thin and handle HTTP concerns; workflows spanning several models, external services or transactions go in a service layer that is easy to unit test.

</QA>

<CheatSheet>

| Layer | File | Example |
| --- | --- | --- |
| Model | `models.py` | `class Product(models.Model)` |
| View | `views.py` | `def product_list(request)` |
| Template | `templates/app/*.html` | `{% for p in products %}` |
| URLs | `urls.py` | `path("", views.product_list)` |
| API output | `serializers.py` | `ProductSerializer` |
| Workflows | `services.py` | `place_order(user, cart)` |

MVC Controller ≈ Django View · MVC View ≈ Django Template
