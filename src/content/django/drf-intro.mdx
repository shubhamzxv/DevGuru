<Analogy>

Your Django shop already has a kitchen (models, ORM, auth). **DRF** adds a **delivery counter**: standard packaging (serializers → JSON), an order window per item (views), a menu board (routers and the browsable API), and rules about who can order what (permissions, throttling), so mobile apps and React frontends can order too.

</Analogy>

## Simple explanation

```bash
pip install djangorestframework django-filter
```

```python
INSTALLED_APPS += ["rest_framework", "rest_framework.authtoken", "django_filters"]

REST_FRAMEWORK = {
    "DEFAULT_AUTHENTICATION_CLASSES": [
        "rest_framework.authentication.TokenAuthentication",
        "rest_framework.authentication.SessionAuthentication",
    ],
    "DEFAULT_PAGINATION_CLASS": "rest_framework.pagination.PageNumberPagination",
    "PAGE_SIZE": 3,
}
```

The building blocks (each has its own topic next):

| Piece | Job | Django equivalent |
| --- | --- | --- |
| **Serializer** | model ↔ JSON, validation | Form / ModelForm |
| **APIView / generic views** | handle requests | View / generic CBVs |
| **ViewSet + Router** | all CRUD actions + URLs | — |
| **Request / Response** | parsed `request.data`, content negotiation | HttpRequest / HttpResponse |
| **Authentication** | who is calling (Session, Token, JWT) | auth middleware |
| **Permissions** | may they do it (`IsAuthenticated`, custom) | permissions |
| **Pagination, filtering, throttling** | big lists, search, rate limits | — |
| **Browsable API** | clickable HTML version of every endpoint | — |

A complete CRUD API in a few lines:

```python
# serializers.py
class ProductSerializer(serializers.ModelSerializer):
    class Meta:
        model = Product
        fields = ["id", "name", "price", "stock", "category"]

# api.py
class ProductViewSet(viewsets.ModelViewSet):
    queryset = Product.objects.select_related("category").order_by("id")
    serializer_class = ProductSerializer

# urls.py
router = DefaultRouter()
router.register("products", ProductViewSet, basename="product")
urlpatterns = [path("api/", include(router.urls))]
```

That gives `GET/POST /api/products/` and `GET/PUT/PATCH/DELETE /api/products/<id>/`, validation, pagination and docs-like browsable pages.

Alternatives: **Django Ninja** (FastAPI-style typed APIs on Django), plain `JsonResponse` views for tiny needs. Generate OpenAPI docs for DRF with **drf-spectacular**.

<Mistakes>

<Mistake title="Building APIs with plain JsonResponse everywhere">

<Wrong>

```python
def products(request):
    data = [{"id": p.id, "name": p.name, "price": str(p.price)} for p in Product.objects.all()]   # no validation, no auth, no paging
    return JsonResponse(data, safe=False)
```

</Wrong>

<Right>

```python
class ProductViewSet(viewsets.ReadOnlyModelViewSet):
    queryset = Product.objects.order_by("id")
    serializer_class = ProductSerializer
```

</Right>

</Mistake>

<Mistake title="Leaving the default permissions open">

<Wrong>

```python
REST_FRAMEWORK = {}      # DEFAULT_PERMISSION_CLASSES = AllowAny: every endpoint is public and writable
```

</Wrong>

<Right>

```python
REST_FRAMEWORK = {"DEFAULT_PERMISSION_CLASSES": ["rest_framework.permissions.IsAuthenticated"]}
# open specific read-only endpoints explicitly
```

</Right>

</Mistake>

</Mistakes>

<InterviewQA>

<QA q="What is Django REST Framework?">

A toolkit on top of Django for building Web APIs: serializers for converting and validating data, APIView/generic views/ViewSets for request handling, routers for URL generation, pluggable authentication, permissions, throttling, pagination, filtering, content negotiation and a browsable HTML API.

</QA>

<QA q="What is the difference between a Django view and a DRF APIView?">

APIView receives a DRF Request (parsed `request.data` for JSON, form or multipart), returns a Response that is rendered according to content negotiation, runs authentication, permission and throttling checks before the handler, and converts exceptions like ValidationError or NotAuthenticated into proper HTTP error responses.

</QA>
