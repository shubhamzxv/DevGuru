## Simple explanation

**Scenario questions: say the steps**

- "**A page is slow**": django-debug-toolbar → query count (N+1 → `select_related`/`prefetch_related`), missing indexes (`EXPLAIN`), `only()`/`values()`, pagination, caching with Redis, move heavy work to Celery
- "**Prevent overselling stock**": `filter(pk=id, stock__gte=qty).update(stock=F("stock") - qty)` + check rows updated, or `select_for_update()` in `transaction.atomic()`, plus a CHECK constraint
- "**Users must only see their own orders**": `get_queryset()` filtered by `request.user` (404 for others), owner set in `perform_create`, object permission class, tests for it
- "**Send an email after an order**": Celery task with the order id, `transaction.on_commit`, retries, idempotent
- "**Add a field to a big table**": nullable/default → deploy → backfill in batches → NOT NULL; `sqlmigrate` to review; migrate as a deploy step
- "**Design the API for a shop**": ModelSerializers, ViewSets + router, JWT/Token auth, `IsAuthenticated` default, pagination, django-filter/search/ordering, throttling, drf-spectacular docs
- "**Deploy it**": DEBUG off, env vars/Secrets Manager, Gunicorn behind Nginx/ALB, collectstatic → S3/CloudFront, RDS, Redis, migrations, `check --deploy`, CI tests

## Code example

The order flow that interviewers love, in one service function:

```python
from django.db import transaction
from django.db.models import F

class OutOfStock(Exception):
    pass

@transaction.atomic
def place_order(user, cart: dict[int, int]) -> Order:
    order = Order.objects.create(customer=user, status=Order.Status.PENDING)
    products = Product.objects.in_bulk(cart.keys())                      # 1 query for all products
    items = []
    for product_id, qty in cart.items():
        updated = Product.objects.filter(pk=product_id, stock__gte=qty).update(stock=F("stock") - qty)
        if not updated:
            raise OutOfStock(products[product_id].name)                  # rolls back everything
        items.append(OrderItem(order=order, product=products[product_id], quantity=qty,
                               price=products[product_id].price))
    OrderItem.objects.bulk_create(items)                                 # 1 INSERT for all lines
    transaction.on_commit(lambda: send_order_email.delay(order.pk))      # only if committed
    return order
```

```output
place_order(asha, {1: 1, 4: 2})   → Order #4 (pending); stock: Clean Code 12 → 11, USB Cable 40 → 38; email queued after commit
place_order(asha, {2: 1})         → OutOfStock("Fluent Python"); no order row, no stock change (atomic rollback)
```

<InterviewQA>

<QA q="Explain the Django request-response cycle.">

The web server hands the request to Gunicorn/Uvicorn, which calls Django's WSGI/ASGI handler; Django builds an HttpRequest, runs middleware in order (security, sessions, CSRF, authentication), resolves the URL to a view with its parameters, the view uses models/forms/serializers/templates and returns an HttpResponse, which passes back through middleware in reverse before going to the client.

</QA>

<QA q="How do you optimise Django ORM performance?">

Measure query counts and slow queries first, then use select_related/prefetch_related against N+1, only/defer/values to fetch less, annotate/aggregate to compute in SQL, bulk_create/bulk_update/update for batch writes, indexes and constraints in Meta, pagination, iterator() for big exports, caching for hot data, and assertNumQueries in tests to prevent regressions.

</QA>

<QA q="How does DRF handle authentication, permissions and throttling?">

For each request APIView runs authentication classes (Session, Token, JWT) to set request.user, then permission classes (has_permission, and has_object_permission when get_object is called), then throttles; failures become 401, 403 or 429 responses. Defaults are set in REST_FRAMEWORK and can be overridden per view or action.

</QA>

<QA q="What are Django's main security protections?">

CSRF middleware with tokens, auto-escaping in templates against XSS, parameterised ORM queries against SQL injection, clickjacking protection, strong password hashing, secure session handling, and deployment settings for HTTPS, HSTS and secure cookies checked by `manage.py check --deploy`.

</QA>

</InterviewQA>
