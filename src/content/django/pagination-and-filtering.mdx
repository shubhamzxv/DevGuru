## Simple explanation

**Pagination**

```python
REST_FRAMEWORK = {
    "DEFAULT_PAGINATION_CLASS": "rest_framework.pagination.PageNumberPagination",
    "PAGE_SIZE": 3,
}
```

| Class | Query | Good for |
| --- | --- | --- |
| `PageNumberPagination` | `?page=2` (`page_size_query_param` to let clients choose, with `max_page_size`) | classic pages |
| `LimitOffsetPagination` | `?limit=20&offset=40` | "load more" with offsets |
| `CursorPagination` | `?cursor=cD0yMDI2...` | huge or fast-changing tables, infinite scroll; stable and fast, no page numbers |

Response shape: `{"count": 7, "next": "...?page=2", "previous": null, "results": [...]}`.

Offset pagination gets slow on big tables (`OFFSET 1000000` still reads those rows) and can skip/duplicate items when rows are inserted; cursor pagination avoids both.

**Filtering, search and ordering**

```python
from django_filters.rest_framework import DjangoFilterBackend
from rest_framework import filters

class ProductViewSet(viewsets.ModelViewSet):
    ...
    filter_backends = [DjangoFilterBackend, filters.SearchFilter, filters.OrderingFilter]
    filterset_fields = ["category__slug", "is_active"]   # ?category__slug=electronics&is_active=true
    search_fields = ["name"]                             # ?search=python  (icontains; "^name" = startswith, "=name" exact)
    ordering_fields = ["price", "name"]                  # ?ordering=-price
    ordering = ["id"]                                    # default
```

For ranges and custom names use a `FilterSet`:

```python
import django_filters

class ProductFilter(django_filters.FilterSet):
    min_price = django_filters.NumberFilter(field_name="price", lookup_expr="gte")
    max_price = django_filters.NumberFilter(field_name="price", lookup_expr="lte")
    category = django_filters.CharFilter(field_name="category__slug")

    class Meta:
        model = Product
        fields = ["category", "is_active"]
# filterset_class = ProductFilter  →  ?min_price=200&max_price=1000&category=books
```

Always define a stable ordering (pagination over an unordered queryset can repeat rows), add **database indexes** for filtered/sorted columns, and whitelist `ordering_fields`.

## Code example

```output
GET /api/products/
  {"count": 7, "next": "http://testserver/api/products/?page=2", "previous": null,
   "results": [{"id": 1, "name": "Clean Code", ...}, {"id": 2, "name": "Fluent Python", ...}, {"id": 3, "name": "Django for APIs", ...}]}

GET /api/products/?page=3
  {"count": 7, "next": null, "previous": "http://testserver/api/products/?page=2",
   "results": [{"id": 7, "name": "Rubik Cube", "price": "299.00", "stock": 20, "category": 3, "category_name": "Toys", "in_stock": true}]}

GET /api/products/?search=python                                → ["Fluent Python"]
GET /api/products/?category__slug=electronics&ordering=-price  → [("Keyboard", "2499.00"), ("Headphones", "1499.00"), ("USB Cable", "199.00")]
```

```sql
CREATE TABLE product (id INTEGER PRIMARY KEY, name TEXT, price REAL, category TEXT);
INSERT INTO product VALUES (1,'Clean Code',450,'books'),(2,'Fluent Python',899,'books'),(3,'Django for APIs',650,'books'),
  (4,'USB Cable',199,'electronics'),(5,'Headphones',1499,'electronics'),(6,'Keyboard',2499,'electronics'),(7,'Rubik Cube',299,'toys');

-- ?page=3 with PAGE_SIZE 3 → OFFSET 6
SELECT COUNT(*) FROM product;
SELECT id, name FROM product ORDER BY id LIMIT 3 OFFSET 6;
-- ?category__slug=electronics&ordering=-price
SELECT name, price FROM product WHERE category = 'electronics' ORDER BY price DESC;
-- cursor style: "the next 3 after id 3" (no OFFSET, uses the index)
SELECT id, name FROM product WHERE id > 3 ORDER BY id LIMIT 3;
```

<InterviewQA>

<QA q="What pagination styles does DRF offer?">

PageNumberPagination (`?page=`), LimitOffsetPagination (`?limit=&offset=`) and CursorPagination (opaque cursor based on an ordering field). Page-number and limit-offset are simple and allow jumping, but OFFSET gets slow on large tables and can skip or duplicate rows when data changes; cursor pagination is consistent and fast for infinite scrolling but cannot jump to a page number.

</QA>

<QA q="How do you implement filtering and search in a DRF API?">

Add filter backends: DjangoFilterBackend with filterset_fields or a FilterSet class for exact matches and ranges, SearchFilter with search_fields for text search, and OrderingFilter with whitelisted ordering_fields; all are driven by query parameters and documented in the browsable API. Back them with database indexes.

</QA>

<CheatSheet>

| Need | Code / URL |
| --- | --- |
| Default paging | `DEFAULT_PAGINATION_CLASS` + `PAGE_SIZE` |
| Page / offset / cursor | `?page=2` · `?limit=20&offset=40` · `?cursor=...` |
| Exact filters | `DjangoFilterBackend` + `filterset_fields` → `?category__slug=books` |
| Ranges | `FilterSet` with `lookup_expr="gte"` → `?min_price=200` |
| Search | `SearchFilter` + `search_fields` → `?search=python` |
| Sort | `OrderingFilter` + `ordering_fields` → `?ordering=-price` |
| Default order | `ordering = ["id"]` |

</CheatSheet>
