<Analogy>

The **back office of a shop** where staff update prices, check orders and add stock, while customers only see the shop floor. Django builds this back office for you from the models, like a furnished staff room that comes with the building.

</Analogy>

## Simple explanation

```bash
python manage.py createsuperuser
python manage.py runserver        # → /admin/
```

Minimal: `admin.site.register(Product)`. Useful: a `ModelAdmin`:

```python
from django.contrib import admin
from .models import Category, Order, OrderItem, Product

@admin.register(Product)
class ProductAdmin(admin.ModelAdmin):
    list_display = ["name", "category", "price", "stock", "is_active"]   # columns
    list_filter = ["category", "is_active"]                              # right sidebar
    search_fields = ["name"]                                             # search box
    list_editable = ["price", "stock"]                                   # edit in the list
    list_select_related = ["category"]                                   # avoid N+1 in the list
    ordering = ["name"]
    autocomplete_fields = ["category"]                                   # searchable dropdown
    actions = ["mark_out_of_stock"]

    @admin.action(description="Mark selected products out of stock")
    def mark_out_of_stock(self, request, queryset):
        updated = queryset.update(stock=0)
        self.message_user(request, f"{updated} products updated.")

class OrderItemInline(admin.TabularInline):        # edit lines inside the order page
    model = OrderItem
    extra = 0
    autocomplete_fields = ["product"]

@admin.register(Order)
class OrderAdmin(admin.ModelAdmin):
    list_display = ["id", "customer", "status", "created_at"]
    list_filter = ["status", "created_at"]
    date_hierarchy = "created_at"
    inlines = [OrderItemInline]
    readonly_fields = ["created_at"]

@admin.register(Category)
class CategoryAdmin(admin.ModelAdmin):
    search_fields = ["name"]                       # required for autocomplete_fields above
    prepopulated_fields = {"slug": ["name"]}
```

**Access**: users need `is_staff=True` to log in, plus model permissions (`view`, `add`, `change`, `delete`) via groups; superusers can do everything. Customise per user with `get_queryset`, `has_change_permission`, `get_readonly_fields`.

Production tips: move the URL (`path("staff-9x2/", admin.site.urls)`), require strong passwords and 2FA (django-otp), restrict by IP or VPN, keep `LogEntry` history (the admin records every change), and use `list_select_related`/`get_queryset` to keep pages fast.

The admin is for **trusted staff**, not a customer-facing UI.

```python
# store/admin.py — show a computed column and a coloured status
from django.contrib import admin
from django.db.models import F, Sum
from django.utils.html import format_html

from .models import Order

@admin.register(Order)
class OrderAdmin(admin.ModelAdmin):
    list_display = ["id", "customer", "coloured_status", "total"]
    list_select_related = ["customer"]

    def get_queryset(self, request):
        qs = super().get_queryset(request)
        return qs.annotate(_total=Sum(F("items__price") * F("items__quantity")))   # one query, no N+1

    @admin.display(description="Total", ordering="_total")
    def total(self, obj):
        return obj._total

    @admin.display(description="Status")
    def coloured_status(self, obj):
        colour = {"paid": "green", "pending": "orange", "cancelled": "red"}.get(obj.status, "grey")
        return format_html('<b style="color:{}">{}</b>', colour, obj.get_status_display())
```

<Mistakes>

<Mistake title="Slow admin list pages">

<Wrong>

```python
list_display = ["name", "category"]      # one extra query per row to fetch the category
```

</Wrong>

<Right>

```python
list_display = ["name", "category"]
list_select_related = ["category"]
```

</Right>

</Mistake>

<Mistake title="Everyone is a superuser">

<Wrong>

```text
All staff accounts are superusers "to keep it simple": anyone can delete orders or change users.
```

</Wrong>

<Right>

```text
Groups such as "Catalog editors" (product add/change) and "Support" (order view/change), is_staff=True, no superuser.
```

</Right>

</Mistake>

<InterviewQA>

<QA q="What is the Django admin and how do you customise it?">

An automatically generated CRUD interface for registered models, for staff users. Customise with ModelAdmin options (list_display, list_filter, search_fields, list_editable, ordering, readonly_fields, fieldsets, inlines, autocomplete_fields, prepopulated_fields), custom actions, computed display methods, get_queryset for performance and permission hooks for access control.

</QA>

<QA q="How do you make admin list pages fast?">

Use list_select_related or override get_queryset with select_related/prefetch_related and annotations for computed columns, add indexes for list_filter and search fields, limit expensive list_display methods, use autocomplete_fields or raw_id_fields for large foreign keys, and set list_per_page.

</QA>

<QA q="How is the admin secured?">

Only active users with is_staff can log in; each model action requires the corresponding permission unless the user is a superuser; changes are logged in LogEntry. In production also change the admin URL, enforce strong passwords and 2FA, restrict access by network, and use HTTPS.

</QA>

<CheatSheet>

| Need | Option |
| --- | --- |
| Register | `@admin.register(Model)` + `class XAdmin(admin.ModelAdmin)` |
| Columns / filters / search | `list_display` · `list_filter` · `search_fields` |
| Inline edit in list | `list_editable` |
| Fast lists | `list_select_related` · `get_queryset()` |
| Related rows | `inlines = [ItemInline]` |
| Big FKs | `autocomplete_fields` · `raw_id_fields` |
| Bulk work | `actions` + `@admin.action` |
| Slug from name | `prepopulated_fields = {"slug": ["name"]}` |
| Access | `is_staff` + groups/permissions |

</CheatSheet>
