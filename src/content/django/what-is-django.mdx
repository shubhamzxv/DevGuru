## Simple explanation

Django (2005, "the web framework for perfectionists with deadlines") gives you, out of the box:

| Battery | What it does |
| --- | --- |
| **ORM** | Python classes ↔ database tables, queries without SQL |
| **Migrations** | versioned schema changes (`makemigrations`, `migrate`) |
| **Admin** | a complete back office to manage your data, generated from models |
| **Auth** | users, passwords (hashed), login/logout, permissions, groups |
| **URL routing + views** | map URLs to Python functions or classes |
| **Templates** | HTML with variables, loops, inheritance |
| **Forms** | validation and HTML rendering |
| **Security** | CSRF protection, XSS auto-escaping, SQL injection safe ORM, clickjacking headers |
| **Extras** | sessions, caching, email, i18n, signals, testing tools |

Plus a huge ecosystem: **Django REST Framework** (APIs), Celery, django-filter, django-allauth, django-storages (S3).

Who uses it: Instagram, Pinterest (early), Mozilla, Disqus, many fintech and e-commerce backends.

Typical commands:

```bash
pip install django
django-admin startproject config .        # the project
python manage.py startapp store           # an app
python manage.py makemigrations && python manage.py migrate
python manage.py createsuperuser
python manage.py runserver                # http://127.0.0.1:8000  and  /admin
```

Good fit: e-commerce, booking systems, CMS, dashboards with admin, SaaS products, REST APIs with DRF. Less ideal: tiny single-purpose microservices or heavily async real-time systems (FastAPI or Channels may fit better).

## Code example

A whole feature in three small files:

```python
# store/models.py
from django.db import models

class Product(models.Model):
    name = models.CharField(max_length=100)
    price = models.DecimalField(max_digits=8, decimal_places=2)
    stock = models.PositiveIntegerField(default=0)

# store/admin.py
from django.contrib import admin
from .models import Product
admin.site.register(Product)          # a full CRUD screen at /admin/

# store/views.py
from django.http import JsonResponse
from .models import Product

def cheap_products(request):
    names = list(Product.objects.filter(price__lt=500).values_list("name", flat=True))
    return JsonResponse({"products": names})
```

```output
$ python manage.py makemigrations store
Migrations for 'store':
  store/migrations/0001_initial.py
    + Create model Product
$ python manage.py migrate
  Applying store.0001_initial... OK
GET /cheap/  -> {"products": ["Clean Code", "Rubik Cube", "USB Cable"]}
GET /admin/  -> login page, then a list/add/edit/delete screen for Product
```

<Mistakes>

<Mistake title="Fighting the framework">

<Wrong>

```text
Writing raw SQL everywhere, a custom user table, hand-made password hashing and your own admin screens.
```

</Wrong>

<Right>

```text
Use the ORM, django.contrib.auth (with a custom User model if needed), the admin and forms; customise them where the product needs it.
```

</Right>

</Mistake>

<Mistake title="Using runserver in production">

<Wrong>

```bash
python manage.py runserver 0.0.0.0:80       # development server: single process, not hardened
```

</Wrong>

<Right>

```bash
gunicorn config.wsgi:application -w 3 -b 127.0.0.1:8000    # behind nginx (see Deployment)
```

</Right>

</Mistake>

<InterviewQA>

<QA q="What is Django and why use it?">

A high-level Python web framework that follows "batteries included": ORM with migrations, admin, authentication and permissions, URL routing, templates, forms, caching and strong security defaults. It lets teams build secure, database-backed products quickly with consistent conventions, and DRF extends it for REST APIs.

</QA>

<QA q="What security features does Django provide out of the box?">

CSRF protection middleware and tokens, automatic HTML escaping in templates against XSS, parameterised ORM queries against SQL injection, clickjacking protection (X-Frame-Options), secure password hashing (PBKDF2, Argon2 optional), and settings for HTTPS, HSTS and secure cookies checked by `manage.py check --deploy`.

</QA>
