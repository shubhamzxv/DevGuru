<Analogy>

A **treasure hunt**: each clue tells you where the next clue is hidden. To reach clue 7 you must follow clues 1 to 6 (**O(n) access**). But adding a new clue between 3 and 4 is easy: change clue 3 to point to the new clue, and the new clue to point to 4 (**O(1) insert**).

</Analogy>

## Simple explanation

```text
head → [3 | •] → [7 | •] → [9 | •] → None
        value next
```

| Operation | Linked list | Python list (array) |
| --- | --- | --- |
| Access i-th item | O(n) | O(1) |
| Insert/delete at head | **O(1)** | O(n) |
| Insert/delete after a known node | **O(1)** | O(n) |
| Search | O(n) | O(n) |
| Memory | extra pointer per node | compact |

Variants: **singly** (next), **doubly** (next + prev: O(1) removal of a given node; used in LRU caches with a dict), **circular**.

In real Python code you rarely build linked lists (use `list` or `deque`); in interviews they test **pointer handling**.

**Core techniques**

| Technique | Use |
| --- | --- |
| `prev, curr` walk | reverse a list |
| **Dummy head** node | merging, deleting the head without special cases |
| **Fast & slow pointers** | middle node, cycle detection (Floyd), k-th from end (gap of k) |
| Draw it! | write the pointers on paper before coding |

## Code example

```python
class Node:
    def __init__(self, val, next=None):
        self.val, self.next = val, next

def build(values):
    head = None
    for v in reversed(values):
        head = Node(v, head)
    return head

def to_list(head):
    out = []
    while head:
        out.append(head.val)
        head = head.next
    return out

def reverse(head):
    prev, curr = None, head
    while curr:
        nxt = curr.next        # remember the rest
        curr.next = prev       # flip the pointer
        prev, curr = curr, nxt
    return prev

def middle(head):
    slow = fast = head
    while fast and fast.next:
        slow, fast = slow.next, fast.next.next   # fast moves twice as fast
    return slow.val

def merge_sorted(a, b):
    dummy = tail = Node(0)
    while a and b:
        if a.val <= b.val:
            tail.next, a = a, a.next
        else:
            tail.next, b = b, b.next
        tail = tail.next
    tail.next = a or b
    return dummy.next

def has_cycle(head):
    slow = fast = head
    while fast and fast.next:
        slow, fast = slow.next, fast.next.next
        if slow is fast:
            return True
    return False

print(to_list(reverse(build([1, 2, 3, 4, 5]))))
print(middle(build([1, 2, 3, 4, 5])), middle(build([1, 2, 3, 4, 5, 6])))
print(to_list(merge_sorted(build([1, 4, 9]), build([2, 3, 10]))))
loop = build([1, 2, 3, 4])
loop.next.next.next.next = loop.next          # 4 → 2 makes a cycle
print(has_cycle(loop), has_cycle(build([1, 2, 3])))
```

```output
[5, 4, 3, 2, 1]
3 4
[1, 2, 3, 4, 9, 10]
True False
```

```python
class Node:
    def __init__(self, val, next=None):
        self.val, self.next = val, next

def remove_nth_from_end(head, n):
    dummy = Node(0, head)
    fast = slow = dummy
    for _ in range(n + 1):          # gap of n nodes between fast and slow
        fast = fast.next
    while fast:
        fast, slow = fast.next, slow.next
    slow.next = slow.next.next      # skip the target
    return dummy.next

head = Node(1, Node(2, Node(3, Node(4, Node(5)))))
head = remove_nth_from_end(head, 2)
node, out = head, []
while node:
    out.append(node.val); node = node.next
print(out)                          # [1, 2, 3, 5]

# Try it: remove the 5th from the end (the head). The dummy node makes it work.
```

<Mistakes>

<Mistake title="Losing the rest of the list">

<Wrong>

```python
curr.next = prev          # the pointer to the rest is gone before you saved it
curr = curr.next          # now goes BACKWARDS
```

</Wrong>

<Right>

```python
nxt = curr.next           # save first
curr.next = prev
prev, curr = curr, nxt
```

</Right>

</Mistake>

<Mistake title="Not checking fast.next">

<Wrong>

```python
while fast:
    fast = fast.next.next     # AttributeError when fast.next is None
```

</Wrong>

<Right>

```python
while fast and fast.next:
    fast = fast.next.next
```

</Right>

<InterviewQA>

<QA q="Reverse a singly linked list.">

Walk the list with prev = None and curr = head; at each node save curr.next, point curr.next to prev, then advance prev and curr. When curr is None, prev is the new head. O(n) time, O(1) space. A recursive version uses O(n) stack.

</QA>

<QA q="How do you detect a cycle in a linked list?">

Floyd's tortoise and hare: move slow one step and fast two steps; if there is a cycle they eventually meet, otherwise fast reaches the end. O(n) time, O(1) space. To find the cycle start, reset one pointer to head and move both one step at a time until they meet.

</QA>

<QA q="Why use a dummy head node?">

It gives a fixed node before the real head, so operations that might change or remove the head (merging, deleting, partitioning) use the same code path as any other node; return dummy.next at the end.

</QA>

<CheatSheet>

| Task | Technique |
| --- | --- |
| Reverse | `nxt = c.next; c.next = prev; prev, c = c, nxt` |
| Middle | slow 1 step, fast 2 steps |
| Cycle | Floyd: `slow is fast` |
| k-th from end | gap of k, then move both |
| Merge / delete head | dummy node, return `dummy.next` |
| LRU cache | dict + doubly linked list (or `OrderedDict`) |
| Loop guard | `while fast and fast.next` |

</CheatSheet>
