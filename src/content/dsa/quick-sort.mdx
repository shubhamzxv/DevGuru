<Analogy>

Sorting students by height for a photo. The teacher picks one student (the **pivot**) and says: "everyone shorter, stand on the left; everyone taller, on the right." Now the pivot is exactly in the right place. Then the same is done for the left group and the right group separately.

</Analogy>

## Simple explanation

```text
[7, 2, 9, 4, 3, 8]   pivot = 4
partition → [2, 3] 4 [7, 9, 8]     4 is in its final position
recurse   → [2, 3] and [7, 8, 9]
result    → [2, 3, 4, 7, 8, 9]
```

**Partition** (Lomuto scheme): walk through the range, swapping items smaller than the pivot to the front; finally swap the pivot into place. O(n) for the range.

| Case | When | Time |
| --- | --- | --- |
| Best / average | pivot splits roughly in half | **O(n log n)** |
| Worst | pivot is always the smallest/largest (sorted input + first/last pivot) | **O(n²)** |

**Avoid the worst case**: random pivot, median-of-three, or three-way partitioning when there are many duplicates.

| Property | Quick sort |
| --- | --- |
| Extra space | O(log n) average (recursion), in place |
| Stable | **no** |
| Strengths | fast in practice, cache-friendly, in place |

**Quickselect**: to find the k-th smallest item, partition once and recurse into **only one side** → average **O(n)** (used for "k-th largest", medians, top-k without full sorting).

## Code example

```python
import random

def partition(a, lo, hi):
    """Lomuto: pivot = a[hi]; returns the pivot's final index."""
    pivot = a[hi]
    i = lo
    for j in range(lo, hi):
        if a[j] < pivot:
            a[i], a[j] = a[j], a[i]
            i += 1
    a[i], a[hi] = a[hi], a[i]
    return i

def quick_sort(a, lo=0, hi=None):
    if hi is None:
        hi = len(a) - 1
    if lo < hi:
        r = random.randint(lo, hi)          # random pivot avoids the sorted-input worst case
        a[r], a[hi] = a[hi], a[r]
        p = partition(a, lo, hi)
        quick_sort(a, lo, p - 1)
        quick_sort(a, p + 1, hi)
    return a

def kth_smallest(a, k):
    """Quickselect, average O(n). k is 1-based."""
    a = a[:]
    lo, hi = 0, len(a) - 1
    while True:
        p = partition(a, lo, hi)
        if p == k - 1:
            return a[p]
        if p < k - 1:
            lo = p + 1
        else:
            hi = p - 1

random.seed(1)
demo = [7, 2, 9, 4, 3, 8]
p = partition(demo, 0, len(demo) - 1)       # last item (8) as pivot
print("after one partition:", demo, "pivot index", p)
print(quick_sort([7, 2, 9, 4, 3, 8, 1, 6]))
print("3rd smallest:", kth_smallest([7, 2, 9, 4, 3, 8], 3))
print("2nd largest:", kth_smallest([3, 2, 1, 5, 6, 4], 6 - 2 + 1))
```

```output

[1, 2, 3, 4, 6, 7, 8, 9]
3rd smallest: 4
2nd largest: 5
```

    global calls

                a[i], a[j] = a[j], a[i]; i += 1

<Mistakes>

<Mistake title="Always using the first or last item as pivot">

<Wrong>

```text
Pivot = a[hi] on already sorted data → partitions of size n-1 and 0 → O(n²), deep recursion.
```

</Wrong>

<Right>

```text
Random pivot (swap a random index into hi) or median-of-three.
```

</Right>

</Mistake>

<Mistake title="Assuming quick sort is stable">

<Wrong>

```text
Sort orders by date with quick sort, then expect equal dates to keep their previous order.
```

</Wrong>

<Right>

```text
Use a stable sort (sorted(), merge sort) when the order of equal items matters.
```

</Right>

</Mistake>

<InterviewQA>

<QA q="Explain quick sort and its time complexity.">

Choose a pivot, partition the array so elements smaller than the pivot are on its left and larger ones on its right (the pivot is then in its final position), and recursively sort both sides. Average O(n log n) with O(log n) stack space; worst case O(n²) when partitions are very unbalanced, which random or median-of-three pivots make unlikely.

</QA>

<QA q="How do you find the k-th largest element without sorting everything?">

Quickselect: partition around a pivot and recurse only into the side containing the target index, giving average O(n). Alternatively keep a min-heap of size k (O(n log k)), which is simpler and good for streaming data.

</QA>

<QA q="Why is quick sort often faster than merge sort in practice?">

It sorts in place with sequential memory access, which is cache-friendly, and has small constant factors; merge sort allocates and copies temporary arrays. With good pivot selection the O(n²) worst case is very unlikely.

</QA>
