<Analogy>

Your phone says "storage almost full". **df** is the summary bar (64 GB total, 2 GB free). **du** is the breakdown by app (WhatsApp 20 GB!). **free** is how much of the phone's working memory (RAM) apps are using right now.

</Analogy>

## Simple explanation

**df: disk free, per filesystem**

```bash
df -h          # -h = human sizes (G, M)
df -h /        # only the root disk
df -i          # inodes: you can run out of these with millions of tiny files
```

Watch **Use%**. At 100% writes fail: databases crash, logs stop, deploys fail with "No space left on device".

**du: disk usage, per folder**

```bash
du -sh /var/log                         # total of one folder
du -h --max-depth=1 /var | sort -h      # which subfolder is big
du -sh * | sort -h                      # biggest items here
```

Usual suspects on servers: `/var/log` (logs never rotated), `/var/lib/docker` (old images and containers), `~/.cache`, old backups, core dumps.

Cleaning up safely:

```bash
sudo journalctl --vacuum-size=200M       # shrink systemd logs
docker system prune                      # stopped containers, unused images
sudo apt clean                           # downloaded packages
```

Use **logrotate** so logs do not grow forever.

**free: memory**

```bash
free -h
```

```text
               total   used   free   shared  buff/cache  available
Mem:           3.8Gi  1.2Gi  1.1Gi    12Mi      1.5Gi       2.4Gi
Swap:          2.0Gi     0B  2.0Gi
```

Read **available**, not free: Linux uses spare RAM as cache (`buff/cache`) and gives it back when programs need it, so low "free" is normal.

When memory runs out the kernel's **OOM killer** kills a process (check `dmesg | grep -i oom` or `journalctl -k`). Containers show exit code 137. **Swap** is disk used as slow emergency memory.

Other quick checks: `nproc` (CPU cores), `lscpu`, `cat /proc/meminfo`, `vmstat 1`, `iostat` (disk I/O).

## Code example

```bash
df -h
du -sh logs
free -h
```

```output
Filesystem      Size  Used Avail Use% Mounted on
/dev/sda1        40G   18G   20G  48% /
tmpfs           2.0G     0  2.0G   0% /dev/shm
13K	logs
               total        used        free      shared  buff/cache   available
Mem:           3.8Gi       1.2Gi       1.1Gi        12Mi       1.5Gi       2.4Gi
Swap:          2.0Gi          0B       2.0Gi
```

<Mistakes>

<Mistake title="Deleting a log file that a process still writes to">

<Wrong>

```bash
rm /var/log/app/huge.log     # df still shows the space used: the process holds the file open
```

</Wrong>

<Right>

```bash
sudo truncate -s 0 /var/log/app/huge.log     # empty it in place
# or restart the process after deleting, and set up logrotate
```

</Right>

</Mistake>

<Mistake title="Panicking about low free memory">

<Wrong>

```text
"free shows only 1.1 GB free, the server is out of memory!"
```

</Wrong>

<Right>

```text
Look at "available" (2.4 GB): cache is released automatically when needed.
```

</Right>

</Mistake>

</Mistakes>

<InterviewQA>

<QA q="The disk is full on a server. How do you find and fix it?">

`df -h` to see which filesystem is full, then `du -h --max-depth=1 <mount> | sort -h` repeatedly to find the large directories (often /var/log, /var/lib/docker, backups). Clean safely: rotate or truncate logs, vacuum the journal, prune Docker, remove old artefacts. If space is not freed after deleting, check for deleted-but-open files with `lsof +L1` and restart that process. Prevent recurrence with logrotate, monitoring alerts and a larger volume.

</QA>

<QA q="What is the difference between df and du?">

df reports space used and free per mounted filesystem from the filesystem's own accounting. du walks directories and adds up file sizes. They can disagree, for example when deleted files are still held open by a process (df counts them, du does not).

</QA>

<QA q="What is the OOM killer?">

When the system runs out of memory and swap, the kernel's out-of-memory killer picks a process (based on memory use and oom_score) and kills it with SIGKILL to keep the system alive. It is logged in the kernel log (dmesg); in containers it shows as exit code 137.

</QA>

<CheatSheet>

| Task | Command |
| --- | --- |
| Disk free | `df -h` · `df -i` (inodes) |
| Folder size | `du -sh dir` |
| Biggest here | `du -sh * \| sort -h` |
| Drill down | `du -h --max-depth=1 /var \| sort -h` |
| Memory | `free -h` (read *available*) |
| Cores | `nproc` · `lscpu` |
| OOM events | `dmesg \| grep -i oom` |
| Clean | `journalctl --vacuum-size=200M` · `docker system prune` · `apt clean` |

</CheatSheet>
