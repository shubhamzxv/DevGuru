<Analogy>

A **lock and key** pair: you put a padlock (the **public key**) on the server's door; only your personal key (the **private key**), which never leaves your pocket, opens it. Anyone can see the padlock; nobody can copy your key from it.

**SSH** is the secure tunnel through that door. **scp** passes parcels (files) through the same tunnel.

</Analogy>

## Simple explanation

**Connect**

```bash
ssh ubuntu@13.233.10.20                     # user@host, port 22
ssh -i ~/keys/shop.pem ec2-user@13.233.10.20   # with a key file (EC2)
ssh -p 2222 deploy@server.example.com       # another port
ssh user@host "df -h && uptime"             # run one command and come back
exit                                        # leave
```

**Key-based login** (better than passwords):

```bash
ssh-keygen -t ed25519 -C "shubham@laptop"   # creates ~/.ssh/id_ed25519 (private) + .pub (public)
ssh-copy-id deploy@server                    # adds the public key to the server's ~/.ssh/authorized_keys
ssh deploy@server                            # no password now
```

- Private key: stays on your machine, `chmod 600`. Never share or commit it
- Public key: goes into `~/.ssh/authorized_keys` on the server
- First connection asks to trust the server's fingerprint; it is saved in `~/.ssh/known_hosts`

**~/.ssh/config** saves typing:

```text
Host shop-prod
    HostName 13.233.10.20
    User ubuntu
    IdentityFile ~/keys/shop.pem
```

Now just `ssh shop-prod`.

**Copy files**

```bash
scp app.tar.gz ubuntu@server:/home/ubuntu/            # upload
scp ubuntu@server:/var/log/nginx/error.log .          # download
scp -r build/ ubuntu@server:/var/www/shop/            # folder
rsync -avz --delete build/ ubuntu@server:/var/www/shop/   # sync: only changed files, faster
```

**Port forwarding** (reach a private database through the server):

```bash
ssh -L 5433:shop-db.internal:5432 ubuntu@bastion     # then connect to localhost:5433
```

**Harden the server** in `/etc/ssh/sshd_config`: `PasswordAuthentication no`, `PermitRootLogin no`, then `sudo systemctl restart ssh`. In AWS, allow port 22 only from your IP in the security group, or use **SSM Session Manager** with no open port at all.

## Code example

```bash
ssh-keygen -t ed25519 -C "shubham@laptop"
chmod 400 shop.pem
ssh -i shop.pem ubuntu@13.233.10.20
scp -i shop.pem release.tar.gz ubuntu@13.233.10.20:/home/ubuntu/
```

<Mistakes>

<Mistake title="Key file permissions too open">

<Wrong>

```bash
ssh -i shop.pem ubuntu@host
# WARNING: UNPROTECTED PRIVATE KEY FILE! ... bad permissions; key ignored
```

</Wrong>

<Right>

```bash
chmod 400 shop.pem
```

</Right>

</Mistake>

<Mistake title="Port 22 open to the whole internet with passwords">

<Wrong>

```text
Security group: 22 from 0.0.0.0/0, PasswordAuthentication yes → thousands of brute-force attempts a day.
```

</Wrong>

<Right>

```text
Key-only login, PermitRootLogin no, 22 open only to your IP (or SSM Session Manager), fail2ban if needed.
```

</Right>

</Mistake>

</Mistakes>

<InterviewQA>

<QA q="How does SSH key authentication work?">

You generate a key pair; the public key is placed in the server's ~/.ssh/authorized_keys. When connecting, the server challenges the client to prove it holds the matching private key by signing data; the private key never leaves the client. It is resistant to password guessing and can be protected with a passphrase.

</QA>

<QA q="What is the difference between scp and rsync?">

Both copy over SSH. scp copies the files you name every time. rsync compares source and destination and transfers only the differences, can delete removed files (`--delete`), resume, preserve permissions and compress, so it is better for repeated deploys and backups.

</QA>

<QA q="How do you secure SSH on a server?">

Use key-based authentication and disable password login and root login in sshd_config, restrict port 22 by firewall or security group to known IPs or use a bastion or SSM Session Manager, keep the server patched, consider fail2ban, and audit /var/log/auth.log.

</QA>

<QA q="How do you connect to a database in a private subnet from your laptop?">

Through an SSH tunnel via a bastion host: `ssh -L 5433:db-host:5432 user@bastion`, then connect the client to localhost:5433. In AWS, SSM Session Manager port forwarding does the same without opening SSH.

</QA>

<CheatSheet>

| Task | Command |
| --- | --- |
| Connect | `ssh user@host` · `ssh -i key.pem user@host` · `-p 2222` |
| One command | `ssh user@host "uptime"` |
| New key | `ssh-keygen -t ed25519` |
| Install key | `ssh-copy-id user@host` |
| Key permissions | `chmod 400 key.pem` · `chmod 700 ~/.ssh` |
| Upload / download | `scp f user@host:/path` · `scp user@host:/path .` |
| Folder | `scp -r dir user@host:/path` · `rsync -avz dir/ user@host:/path/` |
| Tunnel | `ssh -L 5433:db:5432 user@bastion` |
| Shortcut | `~/.ssh/config` with `Host` blocks |

</CheatSheet>
