<Analogy>

A kitchen with simple tools: a **knife** (cut) slices out the part you need, a **sieve** (uniq) removes repeats, a **rack** (sort) puts things in order, a **find-and-replace stamp** (sed) changes one word everywhere, and a **food processor** (awk) can do all of that with rules. Together they turn raw vegetables (logs) into a dish (a report).

</Analogy>

## Simple explanation

**cut**: pick columns

```bash
cut -d, -f2 users.csv           # 2nd field, comma separated
cut -d: -f1 /etc/passwd         # user names
cut -c1-10 file                 # characters 1 to 10
```

**sort** and **uniq**

```bash
sort names.txt                  # alphabetical
sort -n / -rn                   # numeric / numeric descending
sort -t, -k3 -n data.csv        # by 3rd comma-separated column
sort -u                         # sorted and unique
sort | uniq -c                  # count each distinct line (uniq needs SORTED input)
sort | uniq -c | sort -rn       # most frequent first
```

**sed**: stream editor

```bash
sed 's/old/new/' file           # first match on each line
sed 's/old/new/g' file          # every match
sed -i 's/DEBUG=True/DEBUG=False/' settings.env   # edit the file in place
sed -n '10,20p' file            # print lines 10 to 20
sed '/^#/d' nginx.conf          # delete comment lines
sed 's#/old/path#/new/path#g'   # another delimiter when the text has /
```

**awk**: columns, conditions, sums

```bash
awk '{print $1}' access.log                  # 1st column (split on spaces)
awk -F, '{print $1, $3}' users.csv           # -F sets the separator
awk '$9 >= 500 {print $7}' access.log        # condition: only server errors
awk '{sum += $10} END {print sum}' access.log   # total bytes
awk 'NR > 1' data.csv                        # skip the header (NR = line number)
awk '{print NF}' file                        # number of fields per line
```

Also handy: `tr a-z A-Z` (translate characters), `wc -l`, `head`, `tail`, `paste`, `column -t`.

The famous one-liner, top 10 client IPs:

```bash
awk '{print $1}' access.log | sort | uniq -c | sort -rn | head
```

## Code example

The simulator's `logs/access.log` lines look like `IP - - [time] "METHOD PATH HTTP/1.1" STATUS BYTES`, so `$1` is the IP, `$6` the path, `$8` the status and `$9` the bytes.

```bash
awk '{print $8}' logs/access.log | sort | uniq -c | sort -rn
awk '$8 >= 400 {print $8, $6}' logs/access.log
awk '{sum += $9} END {print "total bytes:", sum}' logs/access.log
sed 's/ERROR/❌ ERROR/' logs/app.log | grep ERROR
```

<Mistakes>

<Mistake title="uniq without sort">

<Wrong>

```bash
awk '{print $1}' access.log | uniq -c      # counts only neighbouring duplicates: wrong totals
```

</Wrong>

<Right>

```bash
awk '{print $1}' access.log | sort | uniq -c
```

</Right>

</Mistake>

<Mistake title="Double quotes around awk programs">

<Wrong>

```bash
awk "{print $1}" file        # the shell replaces $1 (empty) before awk runs
```

</Wrong>

<Right>

```bash
awk '{print $1}' file        # single quotes: awk sees $1
```

</Right>

</Mistake>

<Mistake title="sed -i without a backup on an important file">

<Wrong>

```bash
sed -i 's/.*//' /etc/nginx/nginx.conf       # a wrong pattern wipes the file
```

</Wrong>

<Right>

```bash
sed 's/old/new/g' file | less              # preview first
sed -i.bak 's/old/new/g' file              # keeps file.bak
```

</Right>

</Mistake>

<InterviewQA>

<QA q="How do you find the top 10 IP addresses in an access log?">

`awk '{print $1}' access.log | sort | uniq -c | sort -rn | head -10`: extract the IP column, sort so identical IPs are adjacent, count with uniq -c, sort the counts in reverse numeric order and take the first ten.

</QA>

<QA q="How do you replace a string in a file from the command line?">

`sed -i 's/old/new/g' file` edits in place (all occurrences per line with g); use `-i.bak` to keep a backup, another delimiter such as `s#a#b#` when the text contains slashes, and preview without -i first.

</QA>

<QA q="When would you use awk instead of cut?">

cut is simple and fast for fixed delimiters. awk splits on runs of whitespace by default, can filter rows with conditions, reorder and compute fields, keep running totals and print in an END block, so it is better for logs and reports, for example `awk '$9 >= 500 {c++} END {print c}' access.log`.

</QA>

<CheatSheet>

| Task | Command |
| --- | --- |
| Column by delimiter | `cut -d, -f2` |
| Column by whitespace | `awk '{print $1}'` |
| Filter rows | `awk '$3 > 100'` |
| Sum a column | `awk '{s += $2} END {print s}'` |
| Sort | `sort` · `-n` · `-r` · `-k2 -t,` · `-u` |
| Count distinct | `sort \| uniq -c \| sort -rn` |
| Replace | `sed 's/a/b/g'` · `-i` in place · `-i.bak` |
| Lines 10-20 | `sed -n '10,20p'` |
| Delete matching lines | `sed '/pattern/d'` |
| Upper case | `tr a-z A-Z` |

</CheatSheet>
