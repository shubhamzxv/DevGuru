<Analogy>

A car has an **engine** and everything around it: seats, dashboard, radio. The engine alone does not get you to work.

The **Linux kernel** is the engine: it talks to the hardware (CPU, memory, disk, network). A **distribution** (Ubuntu, Debian, Amazon Linux, Red Hat) is the complete car: the kernel plus the shell, commands, package manager and settings.

</Analogy>

## Simple explanation

- **Kernel**: the core program that manages processes, memory, files, devices and the network. Created by Linus Torvalds in 1991, free and open source
- **Shell**: the program that reads your commands, usually **Bash** (or zsh). The **terminal** is the window you type in
- **Distribution (distro)**: kernel + GNU tools + package manager + defaults

| Distro | Package manager | Where you meet it |
| --- | --- | --- |
| Ubuntu / Debian | `apt` | most tutorials, EC2, laptops, `python:3.12-slim` images |
| Amazon Linux 2023 | `dnf` (`yum`) | default on AWS EC2 |
| RHEL / Rocky / CentOS | `dnf` / `yum` | banks, big companies |
| Alpine | `apk` | tiny Docker images |

Why a backend developer must know Linux:

- Almost every **server** and **cloud VM** runs Linux (EC2, DigitalOcean, GCP)
- **Docker containers** are Linux processes
- CI runners (GitHub Actions `ubuntu-latest`) are Linux
- Debugging production means SSH, logs, processes, ports and permissions

Key ideas you will see in every topic:

1. **Everything is a file**: documents, folders, devices (`/dev/sda`), even process info (`/proc`)
2. **Small tools joined with pipes**: `grep ERROR app.log | wc -l`
3. **Users and permissions**: every file has an owner; `root` is the all-powerful admin
4. **Case-sensitive**: `App.py` and `app.py` are different files
5. **No drive letters**: one tree that starts at `/`

The prompt tells you who and where you are:

```text
guru@devguru:~/app$
 |      |      |   |
user  machine folder $ = normal user (# = root)
```

## Code example

```bash
uname -a
cat /etc/os-release
whoami
echo $SHELL
```

VERSION="24.04.1 LTS (Noble Numbat)"

guru
/bin/bash
```

<Wrong>

cat notes.txt
```

<InterviewQA>

<QA q="What is the difference between Linux and a Linux distribution?">

Linux is strictly the kernel, which manages hardware, processes, memory and files. A distribution packages the kernel with a shell, system tools, libraries, a package manager and default configuration, for example Ubuntu, Debian, Amazon Linux or Red Hat Enterprise Linux.

</QA>

<QA q="What is the difference between the kernel, the shell and the terminal?">

The kernel is the core of the OS that talks to hardware. The shell (such as Bash) is a program that interprets the commands you type and starts other programs. The terminal is the window or device that shows text and sends your keystrokes to the shell.

</QA>

<QA q="Why is Linux used for servers?">

It is free and open source, stable, secure with a strong permission model, light enough to run without a graphical desktop, easy to automate through the shell and scripts, and it is the native platform for containers and most cloud services.

</QA>
