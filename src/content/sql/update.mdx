<Analogy>

Think of a contact saved in your phone. Your friend gets a new number. You do not create a new contact. You open the **existing** one and change the number.

`UPDATE` edits rows that are already in the table.

</Analogy>

## Simple explanation

`UPDATE` changes column values in existing rows.

`UPDATE table SET column = value WHERE condition;`

- `SET` says which columns change and to what. Change several by separating them with commas
- `WHERE` says **which rows** change

The most important rule: **an UPDATE without WHERE changes every row in the table.** The database will not warn you.

A safe habit:

1. First write a `SELECT` with the same `WHERE` and look at the rows
2. Then turn it into the `UPDATE`
3. For anything important, do it inside a **transaction**, so you can `ROLLBACK` if the result is wrong

The new value can use the old value: `SET salary = salary * 1.10` gives a 10% raise.

`UPDATE` also obeys constraints. If the new value breaks a rule, the statement fails.

## Code example

```sql
UPDATE employees
SET city = 'Mumbai'                       -- what changes
WHERE name = 'Zoya Fernandes';            -- which row

SELECT name, city FROM employees WHERE name = 'Zoya Fernandes';
```

```output
name           | city
---------------+-------
Zoya Fernandes | Mumbai
```

```sql
UPDATE employees
SET salary = salary + 5000,               -- uses the old value
    city   = 'Pune'                       -- two columns at once
WHERE department_id = 5;

SELECT name, salary, city FROM employees WHERE department_id = 5;
```

```output
name           | salary | city
---------------+--------+-----
Lakshmi Pillai | 69000  | Pune
Manoj Yadav    | 47000  | Pune
```

```sql
UPDATE products
SET stock = stock - (                     -- value from a subquery
  SELECT SUM(quantity) FROM order_items WHERE product_id = products.id
)
WHERE id = 1;

SELECT name, stock FROM products WHERE id = 1;
```

```output
name           | stock
---------------+------
Wireless Mouse | 116
```

<Mistakes>

<Mistake title="Forgetting WHERE">

<Wrong>

```sql
UPDATE employees SET salary = 50000;      -- every one of the 21 employees now earns 50000
SELECT COUNT(DISTINCT salary) FROM employees;
```

</Wrong>

<Right>

```sql
UPDATE employees SET salary = 50000 WHERE id = 19;
SELECT COUNT(DISTINCT salary) FROM employees;
```

</Right>

Without `WHERE`, all rows are updated. Run the matching `SELECT` first, and use a transaction for risky changes.

</Mistake>

<Mistake title="Using AND between the columns in SET">

<Wrong>

```sql
UPDATE employees SET city = 'Pune' AND salary = 60000 WHERE id = 19;
SELECT city, salary FROM employees WHERE id = 19;   -- city is now 0, salary unchanged
```

</Wrong>

<Right>

```sql
UPDATE employees SET city = 'Pune', salary = 60000 WHERE id = 19;
SELECT city, salary FROM employees WHERE id = 19;
```

</Right>

`'Pune' AND salary = 60000` is one true-or-false expression, and its result is stored in `city`. Separate the columns with **commas**.

</Mistake>

</Mistakes>

<InterviewQA>

<QA q="What happens if you run UPDATE without a WHERE clause?">

Every row in the table is updated. To protect against it: run a `SELECT` with the same condition first, wrap the change in a transaction, and in MySQL enable `sql_safe_updates`, which rejects updates without a key in the `WHERE`.

</QA>

<QA q="How do you update a table using values from another table?">

With a correlated subquery (works everywhere), or a join. MySQL: `UPDATE a JOIN b ON a.id = b.a_id SET a.x = b.x`. PostgreSQL: `UPDATE a SET x = b.x FROM b WHERE a.id = b.a_id`.

</QA>

<QA q="How do you give different raises to different departments in one statement?">

Use `CASE` in the `SET`.

```sql
UPDATE employees
SET salary = CASE department_id
               WHEN 1 THEN salary * 1.10
               WHEN 2 THEN salary * 1.05
               ELSE salary
             END;
```

</QA>

<CheatSheet>

| What you want | Code |
| --- | --- |
| Change one column | `UPDATE t SET a = 1 WHERE id = 5;` |
| Change several | `UPDATE t SET a = 1, b = 'x' WHERE id = 5;` |
| Use the old value | `SET stock = stock - 1` |
| Conditional values | `SET a = CASE WHEN ... THEN ... ELSE a END` |
| From another table | `SET a = (SELECT x FROM s WHERE s.id = t.id)` |
| Check first | `SELECT * FROM t WHERE ...` with the same condition |
| Safety net | `BEGIN; UPDATE ...; ROLLBACK;` or `COMMIT;` |

</CheatSheet>
