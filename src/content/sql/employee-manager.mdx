<Analogy>

Imagine one big staff list. Next to each person is the **staff number of their manager**. To compare a person with their manager, you need to look at the list **twice**: once to read the person, once to find the manager's line.

In SQL, reading the same table twice is a **self join**.

</Analogy>

## Simple explanation

Our `employees` table has a `manager_id` column. It points to the `id` of another row **in the same table**.

To put each employee next to their manager, join the table to itself with **two aliases**:

- `e` = the employee
- `m` = the manager
- join condition: `e.manager_id = m.id`

Then the question is just a `WHERE`: `e.salary > m.salary`.

Things the interviewer checks:

- **Aliases**: without them, the database cannot tell the two copies apart
- **INNER vs LEFT join**: an `INNER JOIN` drops people with no manager (the department heads). That is correct here, since they have no one to compare with. Use `LEFT JOIN` when the question is "list every employee **with** their manager's name"
- **The direction of the join**: `e.manager_id = m.id` (find my manager). The reverse, `e.id = m.manager_id`, finds my reports

Related questions solved the same way:

- Employees who are managers (someone's `manager_id` points to them)
- Employees with no manager
- Each manager with their number of reports
- Employees in a **different city** from their manager

In our data, **Imran Ali** (86000) earns more than his manager **Ravi Kumar** (82000).

## Code example

```sql
SELECT e.name   AS employee,  e.salary AS employee_salary,
       m.name   AS manager,   m.salary AS manager_salary
FROM employees AS e
JOIN employees AS m ON e.manager_id = m.id     -- the same table, twice
WHERE e.salary > m.salary;
```

```output
employee  | employee_salary | manager    | manager_salary
----------+-----------------+------------+---------------
Imran Ali | 86000           | Ravi Kumar | 82000
```

Every employee with their manager's name; `LEFT JOIN` keeps the people who have none:

```sql
SELECT e.name AS employee, COALESCE(m.name, '(no manager)') AS manager
FROM employees AS e
LEFT JOIN employees AS m ON e.manager_id = m.id
WHERE e.department_id IN (2, 4)
ORDER BY manager, employee;
```

```output
employee     | manager
-------------+-------------
Farah Sheikh | (no manager)
Vikram Shah  | (no manager)
Gaurav Bose  | Farah Sheikh
Divya Menon  | Ravi Kumar
Imran Ali    | Ravi Kumar
Priya Iyer   | Vikram Shah
Ravi Kumar   | Vikram Shah
```

Each manager with the number of people reporting to them:

```sql
SELECT m.name AS manager, COUNT(e.id) AS reports
FROM employees AS m
JOIN employees AS e ON e.manager_id = m.id     -- reversed: people whose manager is m
GROUP BY m.id, m.name
ORDER BY reports DESC, manager;
```

```output
manager        | reports
---------------+--------
Anita Rao      | 3
Asha Kulkarni  | 2
Meera Nair     | 2
Ravi Kumar     | 2
Rohit Verma    | 2
Vikram Shah    | 2
Farah Sheikh   | 1
Lakshmi Pillai | 1
```

Employees who work in a different city from their manager:

```sql
SELECT e.name, e.city, m.name AS manager, m.city AS manager_city
FROM employees AS e
JOIN employees AS m ON e.manager_id = m.id
WHERE e.city <> m.city
ORDER BY manager, e.name;
```


<Mistakes>

<Mistake title="Joining without aliases">

<Wrong>

```sql
SELECT name FROM employees
JOIN employees ON manager_id = id;   -- Error: ambiguous column name: name
```

</Wrong>

<Right>

```sql
SELECT e.name FROM employees AS e
JOIN employees AS m ON e.manager_id = m.id
LIMIT 3;
```

</Right>

Both copies have the same column names. Each copy needs its own alias, and every column must be prefixed.

</Mistake>

<Mistake title="Joining in the wrong direction">

<Wrong>

```sql
SELECT e.name, m.name AS manager
FROM employees AS e
JOIN employees AS m ON e.id = m.manager_id   -- m is actually e's REPORT, not manager
WHERE e.name = 'Imran Ali';                  -- no rows: Imran manages nobody
```

</Wrong>

<Right>

```sql
SELECT e.name, m.name AS manager
FROM employees AS e
JOIN employees AS m ON e.manager_id = m.id
WHERE e.name = 'Imran Ali';
```

</Right>

Read the condition aloud: "**my** manager_id equals **their** id" means they are my manager.

</Mistake>

</Mistakes>

<InterviewQA>

<QA q="Find employees who earn more than their managers.">

```sql
SELECT e.name
FROM employees e
JOIN employees m ON e.manager_id = m.id
WHERE e.salary > m.salary;
```

A self join with two aliases; the inner join automatically skips employees without a manager.

</QA>

<QA q="What is a self join?">

Joining a table to itself, using two aliases so it is treated as two separate tables. It is used for hierarchical data stored in one table (employee and manager), and for comparing rows within the same table (pairs, duplicates, consecutive records).

</QA>

<QA q="Find all employees in the reporting chain under a given manager, at any depth.">

A self join gives only one level. For all levels, use a recursive CTE: start with the manager, then repeatedly join `employees e ON e.manager_id = previous.id` until no rows are added.

</QA>

<CheatSheet>

| Question | Join and filter |
| --- | --- |
| Earns more than manager | `JOIN employees m ON e.manager_id = m.id WHERE e.salary > m.salary` |
| Everyone + manager name | `LEFT JOIN employees m ON e.manager_id = m.id` |
| Employees with no manager | `WHERE e.manager_id IS NULL` |
| Reports per manager | `JOIN employees e ON e.manager_id = m.id GROUP BY m.id` |
| Who manages nobody | `NOT EXISTS (SELECT 1 FROM employees x WHERE x.manager_id = e.id)` |
| All levels below someone | recursive CTE |
