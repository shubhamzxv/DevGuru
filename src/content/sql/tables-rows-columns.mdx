<Analogy>

Think of a school attendance register. The whole register is about students. Each line is **one student**. Each heading across the top (roll number, name, class) is **one detail** recorded for every student.

In a database, the register is a **table**, each line is a **row**, and each heading is a **column**.

</Analogy>

## Simple explanation

A **table** holds data about one kind of thing: employees, products, orders.

A **column** (also called a **field**) is one detail, such as `name` or `salary`. Every column has a name and a data type.

A **row** (also called a **record**) is one item: one employee, one product.

A **cell** is the single value where a row and a column meet.

The list of tables and their columns is called the **schema**. It is the design of the database.

Most tables have an `id` column whose value is different in every row. This column is the **primary key**. It lets you point at exactly one row.

Tables are linked by storing the id of a row from another table. In `employees`, the column `department_id` holds the id of a row in `departments`. Such a column is called a **foreign key**.

In the playground, press **View schema** to see every table and column of the sample database.

## Code example

```sql
-- * means "all columns". Each line of the result is one row.
SELECT *
FROM departments;
```

```output
id | name        | location
---+-------------+----------
1  | Engineering | Bengaluru
2  | Sales       | Mumbai
3  | Marketing   | Delhi
4  | Finance     | Mumbai
5  | Support     | Pune
6  | Research    | Hyderabad
```

<Mistakes>

<Mistake title="Asking for a column that does not exist">

<Wrong>

```sql
SELECT fullname FROM employees;   -- Error: no such column: fullname
```

</Wrong>

<Right>

```sql
SELECT name FROM employees LIMIT 3;
```

</Right>

Column names must match the schema exactly. Check them with View schema.

</Mistake>

<Mistake title="Mixing up rows and columns">

<Wrong>

```text
"The employees table has 7 rows: id, name, department_id, ..."
```

</Wrong>

<Right>

```text
The employees table has 7 columns (id, name, ...) and 21 rows (one per employee).
```

</Right>

Columns go across and describe details. Rows go down and are the actual items.

</Mistake>

</Mistakes>

<InterviewQA>

<QA q="What is the difference between a row and a column?">

A row (record, tuple) is one complete entry in a table, such as one employee. A column (field, attribute) is one property that every row has, such as salary, with a fixed data type.

</QA>

<QA q="What is a schema?">

The structure of a database: its tables, the columns and data types of each table, and the keys and constraints that link and protect them. In MySQL the word "schema" is also used to mean a database.

</QA>

<QA q="What is a primary key?">

A column, or a set of columns, whose value uniquely identifies each row. It cannot be NULL and cannot repeat. A table can have only one primary key.

</QA>

<QA q="What is a foreign key?">

A column that stores the primary key value of a row in another table, creating a link between the two tables. The database can then refuse values that do not exist in the other table.

</QA>
