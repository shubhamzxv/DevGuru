<Analogy>

Think of counting votes after an election. The officials do not count one big pile. They first sort the ballot papers into separate piles, one pile per party, and then count each pile.

`GROUP BY` makes the piles. The aggregate function counts each one.

</Analogy>

## Simple explanation

`GROUP BY` collects rows with the **same value** in a column into one **group**. Then each aggregate function (`COUNT`, `SUM`, `AVG`, `MIN`, `MAX`) runs once per group.

The result has **one row per group**.

`SELECT department_id, COUNT(*) FROM employees GROUP BY department_id;`

Read it as: "for each department, count the employees".

The golden rule: every column in `SELECT` must be either

- listed in `GROUP BY`, or
- inside an aggregate function

Anything else has no single value for the group. PostgreSQL and strict MySQL reject such a query. SQLite quietly picks a value from some row, which hides the mistake.

More points:

- You can group by several columns. Each different **combination** becomes a group
- You can group by an expression, such as the month of a date
- All NULLs fall into one group
- `WHERE` filters rows **before** grouping. `HAVING` filters groups **after**
- The order of groups is not guaranteed. Add `ORDER BY`

## Code example

```sql
SELECT
  department_id,                     -- the grouping column
  COUNT(*)            AS employees,  -- one count per group
  ROUND(AVG(salary))  AS avg_salary,
  MAX(salary)         AS top_salary
FROM employees
GROUP BY department_id               -- one group per department (NULLs form a group too)
ORDER BY employees DESC;
```

```output
department_id | employees | avg_salary | top_salary
--------------+-----------+------------+-----------
1             | 7         | 113143.0   | 185000
2             | 5         | 90000.0    | 150000
3             | 3         | 83000.0    | 120000
5             | 2         | 53000.0    | 64000
4             | 2         | 103000.0   | 130000
NULL          | 2         | 54000.0    | 58000
```

```sql
SELECT
  category,
  COUNT(*)     AS products,
  SUM(stock)   AS units_in_stock
FROM products
WHERE price < 2000                   -- filter rows first
GROUP BY category                    -- then make groups
ORDER BY category;
```

```output
category    | products | units_in_stock
------------+----------+---------------
Clothing    | 1        | 150
Electronics | 3        | 420
Home        | 3        | 170
Stationery  | 3        | 835
```

```sql
SELECT
  customer_id,
  status,
  COUNT(*) AS orders
FROM orders
GROUP BY customer_id, status         -- one group per (customer, status) pair
ORDER BY customer_id, status
LIMIT 5;
```

```output
customer_id | status    | orders
------------+-----------+-------
1           | delivered | 3
2           | delivered | 2
2           | placed    | 1
3           | cancelled | 1
3           | placed    | 1
```

<Mistakes>

<Mistake title="Selecting a column that is not grouped or aggregated">

<Wrong>

```sql
SELECT department_id, name, COUNT(*)
FROM employees
GROUP BY department_id;   -- Error in PostgreSQL and strict MySQL: name is not in GROUP BY (SQLite shows a random name)
```

</Wrong>

<Right>

```sql
SELECT department_id, COUNT(*) AS employees, MIN(name) AS first_name_a_to_z
FROM employees
GROUP BY department_id;
```

</Right>

A group has many names. Either group by the column, or wrap it in an aggregate.

</Mistake>

<Mistake title="Filtering groups with WHERE">

<Wrong>

```sql
SELECT department_id, COUNT(*) FROM employees
WHERE COUNT(*) > 3 GROUP BY department_id;   -- Error: misuse of aggregate
```

</Wrong>

<Right>

```sql
SELECT department_id, COUNT(*) AS employees FROM employees
GROUP BY department_id HAVING COUNT(*) > 3;
```

</Right>

`WHERE` runs before groups exist. Conditions on aggregates go in `HAVING`.

</Mistake>

</Mistakes>

<InterviewQA>

<QA q="What does GROUP BY do?">

It arranges rows that have the same values in the specified columns into groups, and returns one row per group. It is used with aggregate functions to compute a summary for each group.

</QA>

<QA q="Can you use GROUP BY without an aggregate function?">

Yes. It then returns one row per distinct combination of the grouped columns, the same as `SELECT DISTINCT`.

</QA>

<QA q="What is the order of execution with GROUP BY?">

`FROM` and `JOIN`, then `WHERE`, then `GROUP BY`, then aggregates are computed, then `HAVING`, then `SELECT`, then `ORDER BY`, then `LIMIT`.

</QA>

<QA q="How do you get the number of employees in each department, including departments with none?">

Start from `departments` and `LEFT JOIN` to `employees`, then count a column from the employees side so that NULLs are not counted.

```sql
SELECT d.name, COUNT(e.id) AS employees
FROM departments AS d
LEFT JOIN employees AS e ON e.department_id = d.id
GROUP BY d.id, d.name;
```

</QA>

<CheatSheet>

| What you want | Code |
| --- | --- |
| Count per group | `SELECT city, COUNT(*) FROM t GROUP BY city` |
| Total per group | `SELECT city, SUM(amount) FROM t GROUP BY city` |
| Two levels | `GROUP BY city, status` |
| By month | `GROUP BY strftime('%Y-%m', order_date)` |
| Filter rows first | `WHERE ... GROUP BY ...` |
| Filter groups | `GROUP BY ... HAVING COUNT(*) > 1` |
| Sorted groups | `GROUP BY city ORDER BY COUNT(*) DESC` |

Rule: every selected column is in `GROUP BY` or inside an aggregate.

</CheatSheet>
