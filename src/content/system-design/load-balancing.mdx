## Simple explanation

**What a load balancer does**

- Gives one address (`api.shop.com`) for many servers
- Spreads requests with an **algorithm**
- **Health checks** (`GET /health` every 10 s): stops sending to broken servers
- Often terminates **TLS/HTTPS**, adds headers, logs requests
- Lets you add/remove servers without users noticing (autoscaling, deploys with **connection draining**)

**Algorithms**

| Algorithm | How | Good when |
| --- | --- | --- |
| **Round robin** | 1, 2, 3, 1, 2, 3... | similar servers, similar requests |
| Weighted round robin | bigger servers get more | mixed server sizes, canary 10% |
| **Least connections** | server with fewest active requests | requests of very different length |
| Least response time | fastest recent server | latency-sensitive |
| **IP / key hash** | `hash(client or key) % n` | same user → same server (caching, sessions) |
| **Consistent hashing** | servers on a ring | caches/shards; adding a server moves only ~1/n keys |
| Random / power of two choices | pick 2 random, take the less busy | large fleets, simple and effective |

**Layer 4 vs layer 7**

| | L4 (transport) | L7 (application) |
| --- | --- | --- |
| Sees | IP, port, TCP/UDP | HTTP: path, host, headers, cookies |
| Can | forward connections, very fast | route `/api/*` vs `/images/*`, TLS termination, rewrite, rate limit |
| Examples | AWS NLB, HAProxy (tcp mode) | AWS ALB, Nginx, Envoy, HAProxy (http) |

**Where load balancing happens**: DNS (geo/latency routing between regions) → global/edge LB (CDN) → regional LB → **service-to-service** (client-side LB, service mesh).

**The LB itself must not be a single point of failure**: managed LBs are redundant across zones; self-hosted pairs use failover (keepalived, floating IP).

**Sticky sessions** pin a user to one server (cookie) — easy but uneven load and lost sessions when that server dies; prefer stateless servers with shared session storage.

## Code example

```python
import hashlib, itertools, random
from bisect import bisect

servers = ["s1", "s2", "s3"]

rr = itertools.cycle(servers)
print("round robin:", [next(rr) for _ in range(7)])

active = {"s1": 12, "s2": 3, "s3": 7}
print("least connections →", min(active, key=active.get))

h = lambda key: int(hashlib.md5(key.encode()).hexdigest(), 16)

def modulo_owner(key, nodes):
    return nodes[h(key) % len(nodes)]

class Ring:
    def __init__(self, nodes, vnodes=100):
        self.ring = sorted((h(f"{n}#{i}"), n) for n in nodes for i in range(vnodes))
        self.keys = [k for k, _ in self.ring]
    def owner(self, key):
        return self.ring[bisect(self.keys, h(key)) % len(self.ring)][1]

keys = [f"user:{i}" for i in range(10_000)]
before_mod = {k: modulo_owner(k, servers) for k in keys}
after_mod = {k: modulo_owner(k, servers + ["s4"]) for k in keys}
moved_mod = sum(before_mod[k] != after_mod[k] for k in keys)

ring3, ring4 = Ring(servers), Ring(servers + ["s4"])
moved_ring = sum(ring3.owner(k) != ring4.owner(k) for k in keys)
print(f"add a 4th server: modulo hashing moves {moved_mod / len(keys):.0%} of keys, consistent hashing moves {moved_ring / len(keys):.0%}")

healthy = {"s1": True, "s2": False, "s3": True}
pool = [s for s in servers if healthy[s]]
random.seed(3)
print("after health check, sending to:", sorted({random.choice(pool) for _ in range(20)}))
```

```output
round robin: ['s1', 's2', 's3', 's1', 's2', 's3', 's1']
least connections → s2
add a 4th server: modulo hashing moves 75% of keys, consistent hashing moves 24%
after health check, sending to: ['s1', 's3']
```

<Mistakes>

<Mistake title="hash(key) % n for caches or shards">

<Wrong>

```text
Adding one cache node changes n → about 3/4 of all keys move → massive cache misses (thundering herd on the DB).
```

</Wrong>

<Right>

```text
Consistent hashing (with virtual nodes): only ~1/n of the keys move.
```

</Right>

</Mistake>

<Mistake title="Health check that checks nothing">

<Wrong>

```text
/health always returns 200, even when the server cannot reach the database.
```

</Wrong>

<Right>

```text
A cheap liveness check plus a readiness check of critical dependencies; alarm on the unhealthy target count.
```

</Right>

</Mistake>

<InterviewQA>

<QA q="What is a load balancer and why use one?">

A component that distributes incoming traffic across multiple servers through a single address. It enables horizontal scaling, improves availability by routing around unhealthy servers via health checks, allows zero-downtime deploys and often terminates TLS and routes requests by content.

</QA>

<QA q="Compare round robin, least connections and consistent hashing.">

Round robin cycles through servers evenly, good when requests are similar. Least connections sends to the server with the fewest active requests, good for uneven request durations. Consistent hashing maps keys to servers on a ring so the same key goes to the same server and adding or removing a server moves only a small fraction of keys, which is ideal for caches and shards.

</QA>

<QA q="What is the difference between L4 and L7 load balancing?">

Layer 4 balancers route by IP and port for TCP/UDP without inspecting content, which is very fast and protocol-agnostic. Layer 7 balancers understand HTTP and can route by path, host or headers, terminate TLS, rewrite requests and apply rules, at slightly higher cost.

</QA>

<CheatSheet>

| Need | Choice |
| --- | --- |
| Equal servers | round robin |
| Uneven requests | least connections |
| Canary / mixed sizes | weighted |
| Same key → same node | consistent hashing |
| HTTP routing, TLS | L7 (ALB, Nginx, Envoy) |
| TCP/UDP, extreme speed | L4 (NLB) |
| Remove bad servers | health checks |
| Deploys | connection draining |
| Avoid | sticky sessions, `% n` for caches |

</CheatSheet>
