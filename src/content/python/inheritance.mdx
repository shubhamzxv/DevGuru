<Analogy>

A child gets many things from the parents: the family name, the house, maybe the shop. The child does not earn these again. The child can also add new skills, and can do some things in a different way.

In Python, a class can **inherit** from another class in the same way.

</Analogy>

## Simple explanation

**Inheritance** means one class gets the attributes and methods of another class.

The class that gives is the **parent class** (also called base class or superclass). The class that receives is the **child class** (also called derived class or subclass).

You write the parent in brackets: `class Manager(Employee):`.

The child can do three things:

- **Use** the parent's methods as they are
- **Add** new attributes and methods
- **Override** a method, which means define it again with the same name to change its behaviour

`super()` gives access to the parent. `super().__init__(...)` runs the parent's set-up, so you do not repeat it.

Inheritance models an **"is a"** relationship. A Manager **is an** Employee. If that sentence sounds wrong, do not use inheritance.

Python also allows **multiple inheritance**: a class with more than one parent. The search order for methods is called the **MRO** (Method Resolution Order).

## Code example

```python
class Employee:                              # parent class
    def __init__(self, name, salary):
        self.name = name
        self.salary = salary

    def details(self):
        return f"{self.name} earns {self.salary}"

    def role(self):
        return "Employee"

class Manager(Employee):                     # child class: inherits from Employee
    def __init__(self, name, salary, team_size):
        super().__init__(name, salary)       # let the parent set name and salary
        self.team_size = team_size           # add something new

    def role(self):                          # override the parent's method
        return "Manager"

    def details(self):                       # extend the parent's method
        return super().details() + f" and leads {self.team_size} people"

dev = Employee("Asha", 60000)
boss = Manager("Ravi", 90000, 5)

print(dev.details(), "|", dev.role())
print(boss.details(), "|", boss.role())

print(isinstance(boss, Manager), isinstance(boss, Employee))   # a Manager is an Employee
print(issubclass(Manager, Employee))
print([cls.__name__ for cls in Manager.__mro__])               # the search order
```

```output
Asha earns 60000 | Employee
Ravi earns 90000 and leads 5 people | Manager
True True
True
['Manager', 'Employee', 'object']
```

<Mistakes>

<Mistake title="Forgetting to call the parent's __init__">

<Wrong>

```python
class Person:
    def __init__(self, name):
        self.name = name

class Student(Person):
    def __init__(self, name, roll):
        self.roll = roll            # the parent's set-up never runs

print(Student("Asha", 7).name)   # AttributeError: 'Student' object has no attribute 'name'
```

</Wrong>

<Right>

```python
class Person:
    def __init__(self, name):
        self.name = name

class Student(Person):
    def __init__(self, name, roll):
        super().__init__(name)
        self.roll = roll

print(Student("Asha", 7).name)   # Asha
```

</Right>

When the child defines `__init__`, it replaces the parent's. Call `super().__init__()` to keep the parent's attributes.

</Mistake>

<Mistake title="Using inheritance where it is not an is-a relationship">

<Wrong>

```python
class Engine:
    def start(self):
        return "engine on"

class Car(Engine):          # a car is not an engine
    pass

print(Car().start())   # engine on
```

</Wrong>

<Right>

```python
class Engine:
    def start(self):
        return "engine on"

class Car:
    def __init__(self):
        self.engine = Engine()      # a car HAS an engine

    def start(self):
        return self.engine.start()

print(Car().start())   # engine on
```

</Right>

A car **has an** engine. For "has a", store the other object as an attribute. This is called **composition**.

</Mistake>

<InterviewQA>

<QA q="What is inheritance and what types does Python support?">

Inheritance lets a class reuse another class's code. Python supports **single** (one parent), **multiple** (several parents), **multilevel** (grandparent, parent, child), **hierarchical** (one parent, many children) and **hybrid** (a mix).

</QA>

<QA q="What does super() do?">

It returns a proxy object that forwards method calls to the next class in the MRO, usually the parent. It is used to call the parent's `__init__` or to extend an overridden method without naming the parent class.

</QA>

<QA q="What is MRO?">

Method Resolution Order: the order in which Python searches classes for a method or attribute. Python computes it with the **C3 linearization** algorithm. You can see it with `ClassName.__mro__`. It decides which parent wins in multiple inheritance, including the diamond problem.

```python
class A: pass
class B(A): pass
class C(A): pass
class D(B, C): pass

print([c.__name__ for c in D.__mro__])   # ['D', 'B', 'C', 'A', 'object']
```

</QA>

<QA q="What is the difference between inheritance and composition?">

Inheritance is an "is a" relationship: the child is a kind of the parent. Composition is a "has a" relationship: an object holds other objects as attributes and delegates work to them. Composition is more flexible and is often preferred, because deep inheritance trees are hard to change.

</QA>

<QA q="What is method overriding?">

Defining a method in the child class with the same name as one in the parent. The child's version is used for child objects. It is how a subclass specialises behaviour.

</QA>

| Run the parent's set-up | `super().__init__(...)` |
