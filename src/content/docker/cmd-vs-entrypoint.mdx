<Analogy>

A juice stall. The **ENTRYPOINT** is the juicer machine: it is always the juicer, you cannot turn it into a toaster. The **CMD** is the default fruit: "orange, unless the customer asks for something else".

Order "mango" and you get the juicer with mango. Order nothing and you get the juicer with orange.

</Analogy>

## Simple explanation

| | CMD | ENTRYPOINT |
| --- | --- | --- |
| Role | default command / default arguments | the fixed executable |
| `docker run image ARGS` | ARGS **replace** CMD | ARGS are **appended** to ENTRYPOINT |
| Override | just pass a command | `docker run --entrypoint other image` |
| Typical use | apps: `CMD ["gunicorn", ...]` | tools and wrapper scripts |

How they combine (the final command = ENTRYPOINT + CMD):

| Dockerfile | `docker run img` runs | `docker run img --version` runs |
| --- | --- | --- |
| `CMD ["python", "app.py"]` | `python app.py` | `--version` (error: not a program) |
| `ENTRYPOINT ["python"]` + `CMD ["app.py"]` | `python app.py` | `python --version` |
| `ENTRYPOINT ["python", "app.py"]` | `python app.py` | `python app.py --version` |

**Exec form vs shell form** (important!):

```dockerfile
CMD ["gunicorn", "-b", "0.0.0.0:8000", "app:app"]   # exec form (JSON array): RECOMMENDED
CMD gunicorn -b 0.0.0.0:8000 app:app                 # shell form: runs via /bin/sh -c
```

With the shell form, `/bin/sh` is process 1 and your app is its child, so `docker stop` sends SIGTERM to the shell, the app never hears it, and after 10 seconds Docker kills it with SIGKILL: no graceful shutdown. Always use the **exec form**.

The common production pattern: an **entrypoint script** that prepares things, then hands over to CMD:

```bash
#!/bin/sh
# docker-entrypoint.sh
set -e
python manage.py migrate --noinput
exec "$@"        # replace the shell with the CMD, so it becomes PID 1
```

```dockerfile
COPY docker-entrypoint.sh /usr/local/bin/
ENTRYPOINT ["docker-entrypoint.sh"]
CMD ["gunicorn", "-b", "0.0.0.0:8000", "shop.wsgi"]
```

Now `docker run shop` migrates and starts gunicorn, and `docker run shop python manage.py createsuperuser` migrates and runs your command instead.

<Mistakes>

<Mistake title="Shell form CMD: no graceful shutdown">

<Wrong>

```dockerfile
CMD uvicorn main:app --host 0.0.0.0
# docker stop waits 10 s, then kills the app mid-request
```

</Wrong>

<Right>

```dockerfile
CMD ["uvicorn", "main:app", "--host", "0.0.0.0"]
```

</Right>

</Mistake>

<Mistake title="Forgetting exec in the entrypoint script">

<Wrong>

```bash
python manage.py migrate
"$@"            # the shell stays PID 1 and swallows signals
```

</Wrong>

<Right>

```bash
python manage.py migrate
exec "$@"
```

</Right>

</Mistake>

</Mistakes>

<InterviewQA>

<QA q="What is the difference between CMD and ENTRYPOINT?">

ENTRYPOINT defines the executable that always runs; CMD provides defaults, either the whole command (when there is no ENTRYPOINT) or default arguments to the ENTRYPOINT. Arguments passed to docker run replace CMD, while they are appended to ENTRYPOINT; ENTRYPOINT itself is replaced only with --entrypoint.

</QA>

<QA q="Why prefer the exec form?">

The exec (JSON array) form runs the program directly as PID 1, so it receives signals such as SIGTERM from docker stop and can shut down gracefully. The shell form wraps it in /bin/sh -c, which does not forward signals, so the app is killed after the timeout. The exec form also avoids surprises with shell parsing.

</QA>

<QA q="What would you put in an entrypoint script?">

Startup tasks that must happen at run time rather than build time: waiting for a dependency, running migrations, rendering config from environment variables. It should end with `exec "$@"` so the CMD replaces the script as PID 1.

</QA>

<CheatSheet>

| Want | Write |
| --- | --- |
| Default command for an app | `CMD ["gunicorn", "-b", "0.0.0.0:8000", "app:app"]` |
| Fixed tool, default args | `ENTRYPOINT ["python"]` + `CMD ["app.py"]` |
| Setup then app | `ENTRYPOINT ["docker-entrypoint.sh"]` + CMD, script ends `exec "$@"` |
| Override CMD | `docker run img other command` |
| Override ENTRYPOINT | `docker run --entrypoint sh img` |

Always the exec form (JSON array).

</CheatSheet>
