## Simple explanation

**From prompt to answer** (the most asked "explain how it works" question):

1. **Tokenize**: the text becomes token ids (subwords, BPE)
2. **Embed**: each id becomes a vector; position information is added
3. **Transformer layers**: self-attention mixes information between tokens; feed-forward layers process it. Repeated across many layers
4. **Output scores**: the last position gives a score (logit) for every token in the vocabulary
5. **Sample**: temperature / top-p / top-k pick one token
6. **Append and repeat** until an end token, a stop sequence or max tokens
7. **Decode**: token ids become text, usually streamed

**One line each**

| Topic | Say this |
| --- | --- |
| LLM | predicts the next token; trained on huge text |
| Token | subword unit; ≈ 4 characters; unit of cost and limits |
| Transformer | parallel processing + self-attention |
| Attention | each token weighs every other token |
| Context window | max tokens per request, input + output |
| Stateless | the app resends history |
| Temperature | randomness; 0 for facts and code |
| top-p / top-k | cut unlikely tokens before sampling |
| Hallucination | likely but false; fix with grounding and checks |
| Structured output | JSON by schema + validation + retry |
| Tool calling | model asks, your code runs, result goes back |
| RAG | retrieve relevant text and put it in the prompt |
| Fine-tuning | change behaviour by training; LoRA = cheap adapters |
| Quantization | fewer bits per weight; smaller, slightly less accurate |
| Evals | fixed test set; run on every change |
| Cost | input tokens + output tokens |
| Latency | TTFT, tokens per second, p95; stream |

## Code example

The whole generation loop in a few lines, with a toy model: tokenize, score, sample, append, stop:

```python
import math, random

VOCAB = ["<end>", "I", "like", "love", "tea", "coffee", "."]

def toy_logits(tokens):
    """Scores for the next token, based on the last token only."""
    table = {
        "<start>": {"I": 5},
        "I":       {"like": 3, "love": 2.5},
        "like":    {"tea": 3, "coffee": 2.6},
        "love":    {"coffee": 3, "tea": 2},
        "tea":     {".": 5},
        "coffee":  {".": 5},
        ".":       {"<end>": 5},
    }[tokens[-1]]
    return [table.get(tok, -5) for tok in VOCAB]

def sample(logits, temperature):
    if temperature == 0:
        return VOCAB[logits.index(max(logits))]
    exps = [math.exp(l / temperature) for l in logits]
    return random.choices(VOCAB, weights=exps)[0]

def generate(temperature, max_tokens=8):
    tokens = ["<start>"]
    for _ in range(max_tokens):
        nxt = sample(toy_logits(tokens), temperature)
        if nxt == "<end>":
            break
        tokens.append(nxt)
    return " ".join(tokens[1:])

random.seed(5)
print("temperature 0  :", generate(0), "|", generate(0))
print("temperature 1.5:", generate(1.5), "|", generate(1.5), "|", generate(1.5))
```

```output
temperature 0  : I like tea . | I like tea .
temperature 1.5: I love coffee . | I like tea . | I like tea .
```

Quick sizing questions interviewers like:

```python
context_window = 200_000
system_prompt, history, documents, reserved_output = 1_500, 12_000, 60_000, 4_000

used = system_prompt + history + documents + reserved_output
print("tokens used:", f"{used:,}", "| free:", f"{context_window - used:,}")
print("approx words that fit in the window:", f"{int(context_window * 0.75):,}")

price_in, price_out = 3.0, 15.0            # example $ per million tokens
cost = (used - reserved_output) / 1e6 * price_in + reserved_output / 1e6 * price_out
print(f"cost of this one request: ${cost:.3f}")
```

```output
tokens used: 77,500 | free: 122,500
approx words that fit in the window: 150,000
cost of this one request: $0.280
```

<InterviewQA>

<QA q="Walk through what happens when you send a prompt to an LLM.">

The text is tokenized into ids, converted to embeddings with positional information, and passed through stacked transformer layers where self-attention and feed-forward networks build a contextual representation. The final position is projected to logits over the vocabulary, a decoding strategy picks the next token, it is appended to the input, and the loop repeats until a stop condition. The ids are decoded to text and streamed back.

</QA>

<QA q="What are the main limitations of LLMs?">

Hallucinations, a knowledge cutoff, a finite context window, no memory across requests, non-deterministic output, weak exact arithmetic and counting, sensitivity to prompt wording and injection, latency and per-token cost.

</QA>

<QA q="How would you make an LLM feature production-ready?">

A tested prompt with an eval set; grounding through RAG or tools; structured output with validation; guardrails on input, output and actions; streaming; timeouts, retries and a fallback model; token and cost budgets; caching; logging of prompts, outputs, tokens and latency; and monitoring with human review of samples.

</QA>

<QA q="How do embeddings relate to LLMs?">

Both come from transformer networks. An LLM uses token embeddings internally and generates text. An embedding model outputs one vector for a whole text, so that similar meanings have nearby vectors. Embeddings power semantic search and the retrieval step of RAG, which then feeds an LLM.

</QA>

| Area | Remember |
| --- | --- |
| Pipeline | tokenize → embed → attention layers → logits → sample → repeat → decode |
| Tokens | ≈ 4 chars; BPE subwords; cost and limits |
| Architecture | decoder-only transformer, causal mask |
| Settings | temperature, top-p, top-k, max tokens, stop |
| Context | input + output; stateless; trim, summarise, retrieve |
| Output control | JSON Schema, validation, repair loop |
| Tools | definition → tool call → run → result → answer |
| Adapt | prompt → RAG → tools → fine-tune (LoRA) |
| Deploy smaller | quantization, distillation, small models |
| Measure | evals, TTFT, p95, cost per request |
