<Analogy>

A **closed-book exam** tests only what you remember, and you may guess. An **open-book exam** lets you find the right page first and then write the answer from it. **RAG** turns every question into an open-book exam for the model: **find the page, then answer**.

</Analogy>

## Simple explanation

**RAG** = **R**etrieval-**A**ugmented **G**eneration.

- **Retrieval**: search your documents for the parts that match the question
- **Augmented**: add those parts to the prompt
- **Generation**: the LLM writes the answer using them

**Why it is needed**: an LLM does not know your company's documents, does not know anything after its training cutoff, and guesses when it lacks facts. RAG fixes all three **without retraining** the model.

**Two pipelines**:

**1. Indexing (done once, and again when documents change)**

1. **Load** documents (PDF, HTML, tickets, database rows)
2. **Chunk**: split them into small pieces
3. **Embed**: turn each chunk into a vector with an embedding model
4. **Store** vectors + text + metadata in a **vector database**

**2. Query (done for every question)**

1. **Embed** the question with the same embedding model
2. **Retrieve** the top-k most similar chunks
3. **Build the prompt**: instructions + chunks + question
4. **Generate** the answer, with **citations**

| Benefit | Why |
| --- | --- |
| Fewer hallucinations | the answer is grounded in real text |
| Fresh knowledge | update the index, not the model |
| Citations | you know which chunk each fact came from |
| Access control | retrieve only what this user may see |
| Cheaper than fine-tuning | no training run |

**RAG can still fail**: if retrieval brings the wrong chunks, the answer will be wrong or "I don't know". Most RAG problems are **retrieval problems**.

## Code example

The smallest possible RAG: retrieve by shared words, then build a grounded prompt. Later topics replace word matching with embeddings:

```python
DOCS = [
    "Refunds are processed within 7 working days after we receive the returned item.",
    "Standard delivery takes 3 to 5 days. Express delivery takes 1 day in metro cities.",
    "You can pay by UPI, credit card, debit card or cash on delivery.",
    "The warranty on electronics is 12 months from the date of purchase.",
]

STOPWORDS = {"the", "a", "is", "are", "on", "of", "to", "in", "by", "or", "we", "you", "can", "how", "long", "does", "what", "do", "i"}

def words(text):
    return {w.strip(".,?").lower() for w in text.split()} - STOPWORDS

def retrieve(question, k=2):
    scored = [(len(words(question) & words(doc)), doc) for doc in DOCS]
    scored = [(s, d) for s, d in scored if s > 0]
    return [d for s, d in sorted(scored, key=lambda x: -x[0])[:k]]

def build_prompt(question, chunks):
    context = "\n".join(f"[{i}] {c}" for i, c in enumerate(chunks, 1))
    return (f"Answer using only the sources below. Cite like [1]. "
            f"If the answer is not there, say you don't know.\n\n{context}\n\nQuestion: {question}")

question = "How long does delivery take?"
chunks = retrieve(question)
print(build_prompt(question, chunks))
print()
print("retrieved for 'Do you have a store in Goa?':", retrieve("Do you have a store in Goa?"))
```

```output
Answer using only the sources below. Cite like [1]. If the answer is not there, say you don't know.

[1] Standard delivery takes 3 to 5 days. Express delivery takes 1 day in metro cities.
[2] You can pay by UPI, credit card, debit card or cash on delivery.

Question: How long does delivery take?

retrieved for 'Do you have a store in Goa?': []
```

<Mistakes>

<Mistake title="Blaming the LLM for a retrieval problem">

<Wrong>

```text
"The answer is wrong, let's switch to a bigger model."
```

</Wrong>

<Right>

```text
"First print the retrieved chunks. Is the right passage among them? If not, fix chunking,
embeddings or search before touching the LLM."
```

</Right>

If the right text never reaches the prompt, no model can answer correctly.

</Mistake>

<Mistake title="No way to say 'I don't know'">

<Wrong>

```text
Prompt: "Use the context to answer the question."
```

</Wrong>

<Right>

```text
Prompt: "Answer only from the sources. If they do not contain the answer, say you don't know."
```

</Right>

Without this line the model fills gaps from memory, and you are back to hallucinations.

</Mistake>

</Mistakes>

<InterviewQA>

<QA q="What is RAG and why is it used?">

Retrieval-Augmented Generation retrieves relevant passages from an external knowledge source and adds them to the LLM prompt so the answer is grounded in them. It gives the model private and current knowledge, reduces hallucinations, enables citations and access control, and avoids retraining.

</QA>

<QA q="Explain the RAG pipeline end to end.">

Indexing: load documents, split into chunks, embed each chunk, store vectors with text and metadata in a vector store. Query: embed the question with the same model, retrieve top-k chunks by similarity (often hybrid search plus reranking), build a prompt with instructions, chunks and the question, generate the answer with citations, and optionally validate it.

</QA>

<QA q="RAG vs fine-tuning?">

RAG supplies knowledge at query time: easy to update, citeable, good for large or changing data. Fine-tuning changes the model's behaviour: style, format or a narrow skill. They solve different problems and are often combined.

</QA>

<QA q="Where does RAG usually fail?">

Mostly in retrieval: poor chunking, a weak embedding model for the domain, missing keyword matches (ids, codes), no reranking, wrong metadata filters, or stale indexes. Generation can also ignore the context or mix in memory, which grounded prompts and faithfulness checks address.

</QA>

<CheatSheet>

| Step | What happens |
| --- | --- |
| Load | read PDFs, pages, tickets |
| Chunk | split into pieces (with overlap) |
| Embed | chunk → vector |
| Store | vector DB: vector + text + metadata |
| Query embed | question → vector (same model) |
| Retrieve | top-k nearest chunks |
| Augment | instructions + chunks + question |
| Generate | answer with citations |
| Debug order | retrieval first, then prompt, then model |
| Key line | "answer only from the sources, else say you don't know" |
